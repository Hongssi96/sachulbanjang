### 보고·인수인계

확정된 범위(DEC-013): 관리자용 ‘올라온 보고’ 페이지는 목록·상세 조회를 제공한다. 별도 고용자 인터페이스를 포함한 전체 보고 기능과 백엔드는 생성·조회·수정·삭제를 지원한다.
생성 흐름(DEC-064·DEC-065): 사용자 버튼 클릭 → AI 보고서 생성 → DB 저장·‘올라온 보고’ 목록 등록. 이후 기존 권한에 따라 수정한다. 이메일·메신저 전송은 추후 검토다.
관리자·고용자 모두 백엔드에서 AI 보고서를 생성할 수 있다. 관리자 화면에 생성 기능을 제공할지는 미정이다(DEC-078).
생성 대상(Q-066·DEC-067·DEC-068): 부서·라인·설비 담당을 기본 대상으로 사용하고 복수 담당을 지원한다. 담당 전체를 기본 선택하며 생성 전에 조정할 수 있다.
보고서 기본 기간은 일반은 오늘, 주간은 이번 주, 월간은 이번 달이다. 과거 CSV 시연 중에는 재생 중인 데이터 시각으로 기본 기간을 계산하고 화면에 시연 기준일을 표시한다. 사용자는 생성 전에 기간을 변경할 수 있다(DEC-069·DEC-070).
주간의 ‘이번 주’는 한국 시간 기준 일요일부터 토요일까지이며 진행 중인 주는 생성 기준 시각까지만 집계한다(DEC-184). 월간은 한국 시간 기준 매월 1일부터 말일까지이며 진행 중인 달은 생성 기준 시각까지만 집계한다(DEC-185). 사용자 지정 기간도 유지한다.
주간·월간 보고서는 사용자가 버튼을 눌러 생성하며 종류별 기본 기간을 제공한다. 예약 자동 생성 기능은 추후 범위로 둔다(DEC-186).
관리자가 완료된 보고서를 수정해도 완료 상태를 유지하고 상세 화면에 마지막 수정자·수정 시각과 변경 이력을 제공한다. 별도 재승인 단계나 새 승인 상태는 추가하지 않는다(DEC-187).
보고 상태 변경의 전후 상태·작업자·시각을 기록하고 해당 보고서 조회 권한이 있는 사용자가 상세 화면에서 확인한다. 본문 수정 이력과 구분해 표시하며 별도 승인 단계는 추가하지 않는다(DEC-188).
기록이 없는 기간도 보고서를 등록하고 본문에 ‘조회된 기록 없음’을 표시한다. 미가동이 확인되면 해당 사실을 표시한다. 일부 기록만 있으면 확인된 내용으로 작성한다(DEC-071).
조회 또는 AI 생성 실패 시 오류를 안내하고 보고서는 등록하지 않는다. 사용자는 선택한 조건으로 다시 시도할 수 있다(DEC-072).
일반·주간·월간 보고서는 공통 양식을 사용한다. 집계 기간과 대상, 생산·품질 요약, 기록에서 확인된 주요 이슈를 담고 시연 데이터를 사용하면 본문에 표시한다(DEC-073).
품질 리포트와 AI 보고서에 백엔드 공통 집계 규칙을 적용한다. 보고서의 본문·표·그래프는 같은 집계 결과를 사용하며 그래프는 Matplotlib을 우선 검토한다(DEC-079).
보고서 생성 시 집계 기간·대상·수치를 저장하고 기존 보고서 화면과 PDF의 표·그래프에 사용한다(DEC-080).
서버 접수 시 집계 기준을 고정한다. CSV 시연은 접수 당시 재생 시각이 기준이며, 저장한 기준 시각을 상세 화면과 PDF에 표시한다(DEC-084).
수정 권한이 있는 사용자는 제목과 본문을 편집할 수 있다. 집계 기간·대상·수치는 생성 당시 값을 유지한다(DEC-081).
같은 종류·집계 기간·대상의 조회 가능한 활성 보고서가 있으면 생성 전에 안내한다. 기존 보고서 보기·다시 생성과, 수정 권한이 있는 경우 기존 보고서 수정을 제공한다(DEC-074).
보고 목록은 제목·내용 검색과 분류·상태·작성 기간 필터를 제공하며, 역할별 조회 범위를 적용한다(DEC-020).
보고서 본문을 Markdown 텍스트로 DB에 저장하고 관리자에게 제공하며, PDF 다운로드 요청 시 변환한다(DEC-022·DEC-023). PDF는 서버에 영구 보관하지 않으며 보고서별 다운로드 사용자·시각·횟수를 기록한다. PDF 생성 성공 후 다운로드 응답을 제공한 요청마다 1회로 집계하며, 같은 사용자의 재다운로드도 기록한다(DEC-024). 별도 첨부파일 지원 범위는 논의 중이다.

- [ ] 보고의 필수값, 분류, 상태와 상태 전환 규칙을 정한다.
  - DEC-013에 따라 전체 보고 작성 시 제목·내용·분류 필수, 관련 설비 선택 규칙(DEC-010)을 적용한다.
  - DEC-011에서 설비 이상, 품질 보고, 점검 완료, 기타, 정기보고를 분류로 확정했다. 정기보고는 주간보고와 월간보고로 구분한다.
  - DEC-016에 따라 등록 시 `대기`로 시작하며, 관리자가 `진행 중` 또는 `완료`로 변경한다. DEC-018에 따라 관리자는 완료된 보고를 `진행 중`으로 되돌릴 수 있으며, 변경자·변경 시각·이전 상태를 이력으로 남긴다.
- [ ] 보고 수정·삭제 조건과 변경 이력 보존 여부를 정한다.
  - 보고서 조회 권한이 있는 사용자는 상세 화면의 수정 이력 버튼에서 버전·수정자·시각과 이전 제목·본문을 읽기 전용으로 확인할 수 있다(DEC-138).
  - 보고서 버전을 비교해 동시 수정 충돌을 감지한다. 수정·버전 증가·이력 기록을 같은 트랜잭션에서 처리하며 충돌 시 입력을 유지한다(DEC-137).
  - 완료 보고서의 관리자 수정 후에는 완료 상태를 유지한다. 재처리가 필요하면 직접 진행 중으로 되돌린다(DEC-110).
  - DEC-013에서 수정·삭제 기능 포함을 확정했다. DEC-014·DEC-017에 따라 고용자는 완료 전까지 본인이 작성한 보고를 수정·삭제할 수 있다. 관리자는 완료 여부에 관계없이 모든 보고를 수정·삭제할 수 있다.
  - DEC-015에 따라 수정 시 이전 내용·수정자·수정 시각을 보존하며, 삭제 시 삭제 표시를 남기고 일반 목록에서 숨긴다.
- [x] 인수인계 작성·확인 주체와 확인 상태 규칙을 정한다.
  - 본문 수정은 작성자 본인만 가능하고 관리자도 타인의 본문을 수정할 수 없다. 서버에서 작성자 권한을 검사한다. 관리자의 전체 조회·삭제 권한과 사용자별 확인 표시는 유지한다(DEC-183).
  - 관리자·고용자 모두 전체 노트를 조회한다. 고용자는 본인 담당을 기본 필터로 보고 필터를 변경할 수 있다(DEC-109).
  - 관리자는 전체 노트, 고용자는 본인 노트만 soft delete할 수 있다(DEC-108).
  - DEC-092에 따라 작성자 담당을 기본 대상으로 지정·조정하고 사용자는 담당 관련 노트를 기본으로, 관리자는 전체 노트를 조회한다.
  - DEC-090·DEC-091에 따라 노트를 DB에 저장·공유하고 관리자·고용자 모두 작성·조회할 수 있다. 본인 노트 수정과 읽은 사용자의 확인 표시를 제공한다. 확인자·확인 시각과 수정 시각을 기록하며 수정 후 재확인은 필수로 요구하지 않는다.

### 재고

완료 조건(DEC-041): 완성된 제품을 대상으로 시연 데이터를 사용해 현재 수량 조회, 입고·출고·조정 등록, 변경 이력 확인을 제공한다.

- [ ] 관리 품목, 단위, 입고·출고·조정·폐기 규칙을 정한다.
  - 생산·검사 기록 추가만으로 완제품 재고를 자동 증가시키지 않는다. 사용자의 입고 등록으로 반영하고 초기 수량·조정·정정 등 원장 규칙은 유지한다. 자동 입고 연동은 실제 수량 데이터·업무 기준 확인 후 추후 검토한다(DEC-201).
  - 폐기는 별도 절차 대신 기존 수량 조정에서 감소분과 사유를 기록하는 구현 기본안으로 간소화한다(DEC-150).
  - 현재고가 남은 품목은 삭제를 차단하고 수량을 0으로 정리한 뒤 soft delete한다. 수량 정리에 사유와 이력을 남긴다(DEC-148).
- [x] 음수 재고 허용 여부와 부족 재고 경고 기준을 정한다.
  - 최소 재고 수량의 설정·변경은 관리자만 가능하며 고용자는 조회한다(DEC-131).
  - DEC-089에 따라 현재고가 품목별 최소 수량보다 적으면 ‘재고 부족’을 표시한다. 기준이 없는 품목에는 경고를 표시하지 않는다.
  - DEC-087에 따라 완제품은 정수 ‘개’ 단위로 관리하며 현재고가 0 미만이 되는 출고·조정·정정을 차단한다. 실제 수량 차이는 사유를 남긴 조정으로 맞춘다.
- [x] 현재 수량과 재고 변경 이력 중 기준 데이터를 정한다.
  - 초기 수량·입출고·조정·정정 이력이 기준이다. 별도 현재 수량은 같은 트랜잭션에서 이력과 함께 갱신하고 합계로 검증한다(DEC-139).
  - 보고서와 같은 권한 기준을 적용한다. 고용자는 관리자 확인 전까지 본인 기록을 정정하며 확인 후에는 관리자만 정정한다. 확인자·확인 시각을 기록한다(DEC-088).
  - 잘못 등록한 변경은 원래 기록을 보존하고, 해당 기록에 연결된 정정 사유와 수량을 별도 이력으로 남긴다. 정정 수량은 즉시 반영한다(DEC-085). 관리자는 전체 기록, 고용자는 본인 등록 기록만 정정할 수 있으며 고용자 정정은 관리자 사후 확인 대상이다(DEC-086).

### 일정

기능 범위(DEC-035·DEC-036): 달력·목록·상세 조회를 제공하고 관리자와 고용자 모두 일정을 등록할 수 있다. 관리자는 모든 일정, 고용자는 본인이 등록한 일정만 수정·삭제할 수 있다.

- [ ] 일정 유형, 필수값, 반복 일정 지원 여부를 정한다.
  - DEC-040에 따라 일정은 부가 기능으로 기본 CRUD 중심으로 구현하며 세부 입력값은 구현 기본안을 적용한다. 개별 입력값에 대한 반복 확인은 생략한다.
  - Q-038·Q-039에서 반복·기존 일정 복사 요구를 확인했으며 우선순위는 낮다. 기본 CRUD를 우선하고 반복·복사의 필수 포함 여부는 보류한다. 필수값·유형은 논의 중이다.
- [x] 일정 공개 범위와 수정·삭제 권한을 정한다.
  - DEC-037에 따라 관리자·고용자 모두 전체 일정을 조회한다. DEC-036에 따라 관리자는 모든 일정, 고용자는 본인이 등록한 일정만 수정·삭제할 수 있다.
- [x] 종일 일정, 시작·종료 시각과 시간대 규칙을 정한다.
  - 종일 일정과 시간 지정 일정을 지원한다. 종일 일정은 한국 기준 날짜로 처리하고 시간 지정 일정은 한국 시간 기준으로 입력한다. 종료가 시작보다 뒤인지 FE·BE에서 검증한다. 시간 지정 값의 API 전달·저장은 기존 UTC 계약을 따른다(DEC-168).

### 품질·생산·검사 이력

생산·검사 이력 완료 조건(DEC-026): CSV를 DB에 적재하고 기간·설비·품목·검사 결과로 목록을 필터링하며, 개별 기록의 공정 수치·검사 결과·불량 사유를 상세 조회한다.
데이터 범위 보완(DEC-027): 공정 데이터는 제공 CSV를 활용한다. 별도 검사 데이터는 현재 미확보이며, 임의의 시연 데이터를 사용해 검사 목록·상세 조회를 제공한다. 시연 여부를 표시하고 추후 실제 검사 데이터를 같은 조회 기능에 연동할 수 있게 한다.
품질 리포트 완료 조건(DEC-028): 시연용 검사 데이터로 기간·설비·품목별 검사 건수, 양품·불량 건수, 불량률, 불량 유형별 분포를 조회하며 시연 여부를 표시한다.

- [ ] 생산 실적과 검사 결과의 데이터 원천을 정한다.
  - 검사 데이터는 임의의 시연 데이터로 제공하며 실제 원천·필드는 데이터 확보 후 정한다(DEC-027).
- [ ] 양품·불량 판정 기준과 불량 유형을 정한다.
  - MVP 시연 데이터에 양품·불량 판정과 시연용 불량 유형을 미리 넣고 해당 값으로 집계한다. 불량 판정이지만 유형이 없는 기록은 ‘미분류’로 집계한다. 실제 자동 검사 판정 기준과 유형 매핑은 데이터 확보 후 정한다(DEC-165).
- [ ] 생산량·불량률·가동률 등 KPI 계산식과 집계 기간을 정한다.
  - 실제 수량·집계 기준 확인 전에는 CSV 행 수를 ‘생산 기록 건수’로 표시한다. 실제 생산량은 수량 데이터와 기준 확인 후 제공하고 검사 건수·재고 수량과 구분한다(DEC-190).
  - 가동률도 임의의 시연 데이터로 제공하며 실제 측정값과 구분해 표시한다(DEC-163). 설비별·일자별 계획·실제 가동 시간을 준비하고 `실제 가동 시간 ÷ 계획 가동 시간 × 100`으로 계산한다. 기간·설비별 조회는 시간을 각각 합산한 뒤 계산하며 계획 시간 합계가 0이면 ‘—’로 표시한다. 화면·AI 답변·보고서에 시연 여부를 표시한다(DEC-164).
  - DEC-029에 따라 검사 기록 1건을 집계 단위로 한다. 검사 불량률은 `불량 판정 건수 ÷ (양품 판정 건수 + 불량 판정 건수) × 100`이며, 판정 기록이 없으면 `—`로 표시한다. 나머지 KPI와 집계 기간은 논의 중이다.
- [ ] 과거 검사 기록과 현재 설비 상태의 구분 기준을 정한다.
- [x] 이력 데이터의 보존 기간과 수정 가능 여부를 정한다.
  - MVP 업무 이력은 기간 경과에 따른 자동 영구 삭제 없이 보관하고 운영 전 보존 기간·영구 삭제·백업 정책을 정한다(DEC-157).
  - 관리자의 공정·검사 기록 수정·삭제를 MVP에 포함한다. 수정 전후 값·사유·작업자·시각을 기록하고 삭제에는 soft delete를 적용한다. 고용자는 조회만 가능하다(DEC-158).
  - 신규 공정 기록은 CSV 적재로 등록한다(DEC-159). 검사 결과는 자동 검사 시스템에서 유입되며 별도 수동 등록 화면은 제외한다. 실제 데이터·연동 확보 전에는 시연 데이터를 준비하고 시연 여부를 표시한다(DEC-161, DEC-159 정정).
  - 수정·삭제는 이후 조회·품질 집계·새 AI 조회 및 보고서 생성에 반영하고 기존 보고서의 집계 스냅샷은 유지한다(DEC-160).
  - 공정·검사 기록의 수정·삭제 이력은 관리자만 조회하며 서버에서 권한을 검사한다. 고용자는 수정된 현재 기록을 조회하고 soft delete된 기록은 일반 조회에서 제외한다(DEC-162).
  - 공정·검사 수정·삭제에 버전 검사를 적용한다. 충돌 시 먼저 저장된 변경을 유지하고 작성 중인 입력도 화면에 남겨 최신 기록 확인 후 다시 수정하게 한다. 자동 병합·자동 재저장은 하지 않는다(DEC-178).

### 과거 대화 이력·검색

MVP 대화 답변은 완성 후 한 번에 표시한다. 대기 중에는 실제 데이터 조회·답변 작성 단계를 보여주며 스트리밍은 추후 검토한다(DEC-123).
실패 시 질문을 유지하고 다시 시도를 제공하며, 결과는 같은 질문의 답변 영역에 표시한다(DEC-124).
한 대화의 생성 중 다음 질문 작성은 허용하고 전송은 완료·실패·취소 후에 허용한다. 생성 취소와 질문 수정 후 재전송을 제공하고 취소 요청의 늦은 결과를 배제한다(DEC-125).
대화 답변은 화면 이동·새로고침 후에도 계속 생성하며 돌아오면 결과를 확인할 수 있다. 직접 취소한 요청은 제외한다(DEC-126).

답변에 조회 기간·대상·기준 시각과 시연 여부를 표시하고 근거 보고서·이력의 권한 있는 상세 화면으로 연결한다(DEC-097).
과거 답변을 보존하고 최신 재조회 결과는 같은 대화에 추가한다. 근거 링크 접근 시 현재 권한과 삭제 상태를 검증한다(DEC-098).
근거 데이터의 현재 조회 권한이 없으면 해당 내용이 담긴 과거 답변을 가린다(DEC-099).
근거가 삭제된 과거 답변은 현재 권한을 확인해 참고용으로 표시하고 근거 삭제 사실을 안내한다. 최신 재조회에는 현재 권한과 삭제 필터를 적용한다(DEC-100).
후속 대화에는 현재 권한이 있는 과거 답변과 작성 시각·근거 삭제 상태를 전달한다. 현재 상황을 묻는 질문은 최신 데이터로 조회한다(DEC-101).

AI 조회 권한(DEC-061): 필요한 업무 테이블·컬럼만 공개하고 인증 비밀값은 제외한다. 서버에서 SQL과 사용자별 범위를 검증하며 DB에서 읽기 전용·사용자별 조회 범위를 강제한다. 구체적인 강제 방식은 설계 단계에서 정한다.

AI 조회 실패 처리(DEC-055): SQL 문법·컬럼 오류는 1회 수정 후 재시도하고 재실패 시 실패를 안내한다. 권한 위반은 즉시 차단하며 조회 결과가 없으면 해당 조건의 데이터가 없다고 답한다.

- [x] 대화 기능의 MVP 포함 여부와 실제 AI 호출 여부를 정한다.
  - DEC-030에 따라 실제 AI가 자연어 요청에서 조회 쿼리를 생성하고 공정·보고·생산·검사·품질 데이터를 조회해 답변한다. 대화 내용을 저장한다. Q-031에서 기존 보고 조회 권한 유지와 AI 조회 적용을 확인했다. 고용자는 본인 보고, 관리자는 전체 보고를 조회한다. DEC-057에 따라 SQL 실행은 우선 쿼리당 5초로 제한하고 실제 성능 확인 후 조정한다. 구체적인 쿼리 검증 방식은 논의 중이다.
- [x] 저장할 대화 정보와 보존 기간을 정한다.
  - 대화 이력 조회·검색은 관리자·고용자 모두 본인 대화로 제한한다(DEC-032). 대화방 제목·사용자 질문·AI 답변·대화 시각을 저장한다(DEC-033). 자동 만료 없이 보관하며 사용자가 본인 대화방을 직접 삭제할 수 있다(DEC-034). 삭제 시 실제 제거 방식은 미정이다.
- [x] 검색 대상 필드와 검색 방식을 정한다.
  - 일반 목록 검색은 키워드 부분 일치를 기본으로 한다. 공백 제거 후 빈 검색어는 검색 조건만 해제하며 권한·삭제 규칙과 다른 필터는 유지한다. 정규식·오타 교정·유사도 검색은 MVP에서 제외하고 AI 자연어 조회의 오타 이해는 유지한다. API별 검색 필드는 명시한다(DEC-189).
  - 제목·질문·답변의 키워드 검색과 기간 필터를 제공한다(DEC-033).

## 4. API 계약

DEC-152에서 공통 기본안에 FE·BE가 합의했다. 아래의 이전 ‘FE 검토 대기’는 공통 기본안에 대해 해소되었으며 개별 API·세부 필드의 검토는 남아 있다. [API_SPEC.md](API_SPEC.md)에 합의 기준과 상세 설계 작업을 정리했다.

- [ ] API 기본 경로와 버전 정책을 정한다. 예: `/api/v1`
  - DEC-049의 FE 협의안은 `/api/v1`이다. FE 검토 대기.
- [ ] JSON 필드 명명 규칙을 정한다. 예: `snake_case`, `camelCase`
  - DEC-049의 FE 협의안은 `snake_case`다. FE 검토 대기.
- [ ] 날짜·시간 형식, 저장 기준과 표시 시간대를 정한다.
  - DEC-049의 FE 협의안은 UTC 저장·RFC 3339 전송 및 한국 시간 표시다. FE 검토와 CSV 원본 시간대 확인 대기.
- [ ] 공통 성공 응답 형식을 정한다.
  - DEC-104의 FE 협의안은 단건 데이터 객체, 목록의 items와 페이지 정보, 생성 접수의 작업 ID와 처리 상태다. FE 검토 대기.
- [ ] 공통 오류 응답과 업무 오류 코드 형식을 정한다.
  - DEC-103의 FE 협의안은 HTTP 상태 코드와 code·message·request_id다. 입력 검증 실패 시 필드별 오류 정보를 선택적으로 포함한다. FE 검토 대기.
- [x] 필수·선택·null 허용 필드의 표기 규칙을 정한다.
  - 필드별 필수·생략·null 허용 여부를 명세한다. 부분 수정의 생략은 유지, nullable 필드의 null은 값 제거, 필수값 null은 오류다. FE·BE 모두 검증한다(DEC-155).
- [ ] 목록 페이지네이션 방식을 정한다. 예: offset, cursor
  - DEC-122에 따라 기본 10건·최대 100건으로 사용자 표시 개수 선택과 검색·필터를 지원한다. Q-152에서 하단 페이지 번호를 1~10, 11~20처럼 10개씩 묶어 이동하도록 확인했다. AI 다음 결과 조회와 전체 대상 통계를 지원한다. API 세부 필드는 추가 검토한다.
- [ ] 검색·필터·정렬 쿼리 규칙을 정한다.
  - 서버에서 권한·삭제 규칙과 검색·필터를 적용한 전체 결과를 정렬한 뒤 페이지를 나눈다. 조건 변경 시 첫 페이지, 이후 페이지는 같은 조건을 유지한다. 필드·방향은 API별로 정의한다(DEC-156).
- [x] OpenAPI 등 API 문서화 방식을 정한다.
  - API_SPEC.md와 FastAPI OpenAPI 문서를 함께 관리한다. 팀 절차는 API_DOCUMENTATION_GUIDE.md에 기록했다. 실제 앱·문서 화면은 초기 구현 후 제공한다(DEC-153).
- [x] 호환성이 깨지는 변경의 FE·BE 적용 순서를 정한다.
  - 새 규격 추가 → FE 전환 확인 → 기존 규격 제거를 기본으로 한다. 작은 내부 변경은 적용 시점을 합의한다(DEC-154).
- [ ] FE 담당자의 API 계약 검토·승인 절차를 정한다.

## 5. 데이터베이스

- [x] PostgreSQL 버전을 정한다.
  - PostgreSQL 18을 사용하고 초기 설치·통합 검증 후 패치 버전을 고정한다(DEC-142).
- [x] 테이블·컬럼 명명 규칙을 정한다.
  - 소문자 snake_case를 사용하고 테이블명은 단수형으로 통일한다(DEC-144).
- [x] 기본키 형식을 정한다. 예: bigint, UUID
  - 자동 증가 bigint를 기본으로 한다. 사번·설비 코드는 별도 고유 필드로 관리하며 초기 데이터 연결에 사용한다. 유일성 범위는 실제 데이터와 설계에서 검증한다(DEC-143).
- [x] 생성·수정 시각과 소프트 삭제 적용 기준을 정한다.
  - 업무 리소스에 created_at·updated_at, soft delete 대상에 deleted_at을 둔다. 삭제 전 NULL, 삭제 시 시각을 기록하고 일반 조회에서 제외한다(DEC-145).
  - DEC-093에 따라 휴지통·복구 기능은 추후 범위로 보류하고 MVP는 soft delete로 보존한다.
  - DEC-062에 따라 모든 삭제는 soft delete를 기본으로 한다. 삭제 데이터는 보존하고 일반 조회·검색·AI 조회에서 제외한다. 앞서 남겨둔 대화 삭제 방식의 미정 상태도 이 결정으로 대체한다.
- [ ] 필수값, 유일성, 참조 관계에 적용할 제약조건을 정한다.
  - 설비·품목 삭제가 기존 업무 이력과 보고서를 삭제하거나 과거 조회에서 숨기지 않도록 관계를 보존한다. 신규 선택 대상에서는 제외한다(DEC-147).
  - 사번은 삭제 계정을 포함해 고유하게 유지한다. 작성자 계정 삭제가 보고서·작성자 연결·수정·다운로드 이력을 삭제하지 않도록 설계하며, 관리자는 작성자 활성 여부와 관계없이 활성 보고서를 조회한다(DEC-146).
- [ ] 업무 이력과 감사 로그 저장 범위를 정한다.
  - 현재 조회 권한에 따라 이전 버전 PDF도 다운로드할 수 있고, 다운로드 이력에 해당 버전을 기록한다(DEC-141).
  - PDF 다운로드 이력에 보고서 버전을 기록하고 해당 버전 본문과 저장된 집계 결과로 생성한다(DEC-140).
  - 보고서 다운로드 사용자·시각·횟수를 기록한다(DEC-023·DEC-024). 이력 조회는 해당 보고서의 조회 권한을 따른다(DEC-025).
- [ ] 공정·검사 시계열 데이터의 보존·집계·삭제 정책을 정한다.
- [ ] 주요 조회 조건과 인덱스 기준을 정한다.
- [ ] 개발 초기 데이터와 테스트 데이터 제공 방식을 정한다.
  - 초기 계정·조직·설비·품목 적재는 별도 명령으로 제공하고 서버 시작 시 자동 실행하지 않는다. 재실행 시 중복 생성이나 기존 비밀번호·수정값 덮어쓰기를 방지하며 초기 구성 시 BE/README에 실행 방법을 안내한다(DEC-195).
  - 기본 초기 데이터 적재 중 오류가 나면 해당 실행의 변경을 모두 롤백하고 실패 항목을 안내한다. 수정 후 재실행한다. 대용량 공정 CSV의 배치·오류 처리는 기준 CSV 확인 후 별도로 정한다(DEC-196).
  - 설비·품목 기본정보는 데이터셋과 DB 초기 데이터로 준비하며 별도 등록·편집 관리 화면은 추후 범위다(DEC-149).
  - 최종 CSV 선정 후 검사·재고 시연 데이터를 품목·설비·기간에 맞춰 연결하고 시연 여부를 표시한다. 재고 수량과 생산 기록 건수는 별도다(DEC-136).
  - 사용자별 복수 담당은 계정·근무시간과 함께 DB 초기 데이터로 준비한다. 담당 관리 화면은 추후 범위다(DEC-130).
  - 사용자별 기본 근무 시작·종료 시각은 계정과 함께 DB 초기 데이터로 준비한다. 근무표 편집·외부 근태 연동은 추후 범위다(DEC-116).
  - 공정 CSV 재적재 시 중복을 방지하고, 동일 원본 식별자의 내용 충돌은 기존 기록 보존 및 안내로 처리한다(DEC-076). 기준 CSV와 식별자 범위는 미정이다.
- [ ] 백업·복구 책임과 파괴적 마이그레이션 승인 절차를 정한다.

## 7. 아키텍처·구현 기준

- [x] Router, Service/Domain, Repository의 책임과 의존 방향을 정한다.

- [x] 도메인 예외를 HTTP 오류로 변환하는 기준을 정한다.
  - ARCHITECTURE.md·DOMAIN_MODEL.md·API_SPEC.md에 기술 기본안을 작성했다. 실제 구현·동시성·오류 계약 검증은 TEST_PLAN.md를 따른다.
- [ ] 파일 업로드 필요 여부와 저장 위치·크기·형식 제한을 정한다.
  - 기본 Markdown을 지원하고 본문 HTML·스크립트와 임의의 외부 이미지 로딩은 허용하지 않는다. 서버 생성 그래프는 화면과 PDF에 포함한다. 현재 범위에 S3 등 외부 스토리지를 추가하지 않는다(DEC-170).
  - 그래프는 저장된 집계 스냅샷으로 필요할 때 생성하고 이미지 파일은 영구 보관하지 않는다. 루트 DESIGN.md의 색상·글꼴 등을 참고해 화면·PDF에 공통 그래프 스타일을 적용하고 한글 글꼴·가독성을 확인한다(DEC-171).
  - 그래프만 생성에 실패하면 화면·PDF에서 본문·표를 제공하고 해당 위치에 누락 안내와 확인 가능한 실패 사유를 표시한다. 사용자용 사유에 내부 정보를 노출하지 않고 상세 오류·요청 ID는 서버 로그에 남긴다. PDF 자체 생성 실패는 다운로드 성공 횟수에서 제외한다(DEC-172).
  - 그래프 실패 시 화면에 ‘다시 시도’를 제공한다. 같은 저장 집계로 그래프만 다시 생성하고 PDF 재다운로드에도 같은 집계를 사용하며 본문·수치·보고서 버전은 유지한다(DEC-173).
  - 보고서 본문은 Markdown으로 저장하고 요청 시 PDF로 변환·다운로드한다. PDF 영구 보관 없이 다운로드 이력을 기록한다(DEC-022·DEC-023). 보고서의 별도 첨부파일 업로드는 MVP에서 제외하고 추후 범위로 둔다. 도입 시 형식·용량·권한·저장 방식을 정한다(DEC-169).
- [ ] 배치 또는 백그라운드 작업 필요 여부를 정한다.
  - 다른 화면에서 AI 생성이 실패·중단되면 앱 내 안내와 ‘작업 확인’을 제공한다. 현재 화면을 자동 이동시키지 않고 사용자가 해당 대화·작업에서 사유 확인·재시도를 진행한다(DEC-177).
  - 다른 화면에서 AI 답변·보고서 생성이 끝나면 앱 안에 완료 안내와 ‘결과 보기’를 제공한다. 이메일·메신저·브라우저 푸시는 추후 범위이며 앱 재접속 시 기존 대화·작업·보고서 목록에서 상태·결과를 확인한다. 결과 접근에는 현재 권한을 적용한다(DEC-176).
  - AI 답변·보고서 생성의 전체 처리 시간 상한과 시간 초과 정책은 실제 모델 시험 후 결정한다(Q-175 보류). 화면 이동·새로고침 후에도 서버에서 생성을 계속하는 기존 합의와 SQL 쿼리당 5초 제한은 유지한다.
  - 보고서 본문 생성 실패 시 미완성 보고서는 등록하지 않고 ‘내 생성 작업’에 실패 사유·생성 조건을 남긴다. 재시도는 같은 조건의 새 작업으로 접수하며 새 접수 시점의 데이터를 사용하고 기존 실패 이력은 유지한다(DEC-174).
  - ‘내 생성 작업’에서 진행 중 생성을 취소할 수 있으며 취소 확정 시 보고서를 등록하지 않는다. 완료·등록된 보고서는 기존 권한을 따른다(DEC-127).
  - 수동·자동 로그아웃 후에도 접수된 보고서 생성은 계속하고 재로그인 시 상태와 결과를 확인할 수 있다. 실행에는 현재 권한을 적용한다(DEC-118).
  - 등록된 보고서는 ‘올라온 보고’, 생성 중·실패·중단 작업은 요청자의 ‘내 생성 작업’에 표시한다. 생성 단계와 업무 상태를 구분한다(DEC-096).
  - AI 보고서 생성은 실제 접수·데이터 조회·본문 작성·완료 또는 실패·중단 상태를 표시한다. 대화는 데이터 조회 중·답변 작성 중을 표시한다(DEC-095).
  - 서버 중단으로 끝나지 못한 보고서 생성은 중단 상태를 안내하고 사용자 재시도를 제공한다. 복구 후 자동 재실행은 추후 범위다(DEC-094).
  - AI 보고서 생성은 화면 이동·새로고침과 관계없이 서버에서 계속한다. 요청자는 상태와 결과를 다시 확인할 수 있다(DEC-082). 실행 구조는 설계에서 정한다.
  - 접수 응답을 기다리는 동안 생성 버튼을 비활성화하고, 동일 요청 ID의 재전송에는 기존 작업 또는 결과를 반환한다. 사용자가 명시적으로 다시 생성하면 별도 작업을 접수한다(DEC-083).
