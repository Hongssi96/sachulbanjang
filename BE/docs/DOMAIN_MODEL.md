# 도메인·상태 전환 초안

2026-11-19. 사용자 합의는 REQUIREMENTS.md와 DECISION_HISTORY.md, 구현 구조는 ARCHITECTURE.md를 따른다. 영문 상태 코드는 기술 기본안이며 FE 상세 계약 확인 전이다.

| 대상 | 상태·전환 | 금지·경합 처리 |
| --- | --- | --- |
| 보고 업무 | pending(대기) → in_progress(진행 중) / completed(완료), completed → in_progress | 관리자만 변경. 고용자는 완료 전 본인 제목·본문 수정·삭제. 관리자 본문 수정만으로 완료를 해제하지 않음 |
| AI 작업 | accepted → querying → writing → succeeded / failed / interrupted, 비종료 상태 → cancelled | 단계별 오류 허용. 최종 상태는 원자적으로 한 번 확정. 취소 후 늦은 결과 저장 금지. 성공과 취소 경합은 DB 확정 상태 기준 |
| 보고 재시도 | failed/interrupted → 새 generation_job | 기존 실패 보존, 새 접수 시점 기준, 새 보고서 ID |
| 대화 재시도 | 동일 질문에 새 generation_job | active_job_id 비교로 이전 시도의 늦은 결과 배제. 최신 재조회는 새 질문·답변으로 추가 |
| 재고 사후 확인 | unconfirmed → confirmed | 고용자 본인 정정은 확인 전, 관리자는 확인 후도 정정. 원본 보존·별도 delta |
| 인수인계 확인 | 사용자별 미확인 → 확인 | 본문 수정 후 확인 초기화 강제 없음, 수정 시각 표시 |
| 근무 세션 | active → 연장된 active / ended | 종료 전 10분 구간 실제 작업 시 1시간 연장, 각 종료 시각당 1회. 작업 없으면 종료. 재로그인은 새 세션 |
| 공정 표시 | 재생 중 / 갱신 지연 / 시연 종료, 조회 실패 시 연결 오류 | 설비 자체의 상태 미확인과 데이터 전송 상태를 구분. 재생 종료 뒤 지연으로 덮어쓰지 않음 |

AI 작업 상태와 보고 업무 상태는 다른 필드다. AI 완료 시 보고 업무는 대기로 등록한다. 취소·실패 작업은 보고서 목록에 미완성 보고서를 만들지 않는다. 화면 이동·새로고침·로그아웃 자체는 취소가 아니다.

권한 검사는 실행 시 현재 상태를 읽어 적용한다. 보고서·작업 접수 당시의 권한만 믿고 나중 실행하거나 조회하지 않는다. 작업 요청자 계정이 삭제되거나 필요한 권한을 상실하면 결과를 새로 제공하지 않는다. 기존 보고서는 작성자 삭제와 무관하게 관리자 조회를 유지한다.

삭제는 기본 soft delete지만 재고 원장·감사 이벤트를 일반 리소스처럼 삭제하는 API는 두지 않는다. 원장 취소 의미의 작업은 정정으로 처리한다. 휴지통·복구·영구 삭제 기능은 MVP에 없다.
