# 백엔드 요구사항 초안

기준일은 2026-11-19이다. 요청자와의 결정 대화는 [DECISION_HISTORY.md](DECISION_HISTORY.md)에 보존한다.
이 문서는 최신 합의의 요약이며, 구현 완료를 의미하지 않는다.
의사결정 진행 원칙: 기술 선택·일반 구현 정책은 저장소 규칙과 현업 관행에 따라 AI가 근거를 확인해 정한다. 사용자에게는 미해결 비즈니스 로직·권한·업무 흐름·계산 기준·제품 범위만 질문하고, 기결정·보류 항목의 반복 확인을 피한다. 사용자 합의와 기술 기본안을 구분해 이력에 보존한다(DEC-200).
담당 실명과 목표일은 아직 지정되지 않았다. 미결정 항목은 이 문서 하단과 원본 체크리스트에서 추적한다.

## 1. 제품 범위와 구현 순서

사출성형 업무 관리 웹앱의 1차 MVP에 다음 7개 기능을 포함한다.

1. 실시간 공정
2. 올라온 보고
3. 생산·검사 이력
4. 품질 리포트
5. 과거 대화 이력·검색
6. 일정 상세
7. 재고 관리

캐시, 벡터 DB, 임베딩, RAG 파이프라인은 MVP에서 제외한다.
실제 설비 수집 연동은 추후 범위이며 공정의 CSV 재생을 제공한다.
AI 모델의 최소 기준은 요청자가 전달한 명칭 `gpt 5.6 sol`이다. 상위 모델 채택은 미정이며 실제 API 모델 ID·제공 경로·사용 가능 여부·예산은 확인 대기다(DEC-120). 배포 환경은 팀 논의 대기다.

근거는 DEC-001~003, DEC-005, Q-044, Q-047이다.

## 2. 공통 완료 조건

목록은 기본 10개·최대 100개로 사용자 표시 개수 선택과 검색·필터를 제공한다. 페이지 번호 기반 offset 조회를 사용한다(DEC-122). 하단 페이지 번호는 1~10, 11~20처럼 10개씩 묶어 이동한다(Q-152의 공동 검토에서 확인).
기본 정렬은 보고서·대화방·변경 이력의 최신순과 일정의 시작 시각순이며, 시각 동률에는 ID 순서를 적용한다. 서버에서 권한·삭제 규칙과 검색·필터를 적용한 전체 결과를 사용자 지정 조건으로 정렬한 뒤 페이지를 나눈다. 정렬 변경 시 첫 페이지를 조회하고 이후 페이지에도 같은 조건을 유지한다. 정렬 필드·방향은 API별 허용 목록으로 정의한다(DEC-156).
일반 목록은 키워드 부분 일치로 검색한다. 앞뒤 공백을 제거한 빈 검색어는 검색 조건 없이 조회하며 기존 권한·삭제 규칙과 다른 필터는 유지한다. 정규식·오타 교정·유사도 검색은 MVP에서 제외한다. AI 자연어 조회의 기존 오타 이해 규칙은 유지하고 검색 대상 필드는 API별로 명시한다(DEC-189).

- 기능별 핵심 흐름이 합의된 범위대로 작동한다.
- 서버에서 입력값과 접근 권한을 검증한다.
- FE에서도 전송 전에 해당 작업의 필수값을 검사하고 입력 오류를 안내한다. BE 검증도 함께 적용한다(Q-155).
- 부분 수정에서 생략한 필드는 기존 값을 유지한다. null을 허용하는 필드에 null을 보내면 값을 비우고 필수값의 null은 검증 오류로 처리한다(DEC-155).
- 화면에 로딩·빈 결과·오류 상태를 제공한다.
- 편집 화면에서 미저장 변경이 있는 상태로 다른 화면으로 이동하려 하면 ‘변경사항이 저장되지 않았습니다’ 안내와 ‘나가기 / 계속 편집’을 제공한다. 계속 편집을 선택하면 입력을 유지한다. 자동 초안 저장은 MVP에서 제외한다(DEC-179).
- 영속 데이터는 PostgreSQL에 저장하고 재조회할 수 있다.
- 관련 API·업무 규칙을 문서화하고 합의된 검증을 통과한다.
- 시연 데이터와 실제 연동 상태를 표시한다.
- 모든 리소스 삭제는 soft delete를 기본으로 한다(DEC-062). 삭제 데이터는 보존하고 일반 조회·검색·AI 조회에서 제외한다.
- 휴지통·복구 기능은 추후 범위로 보류한다(DEC-093).
- MVP의 공정·검사·보고서·재고 변경 이력은 기간 경과에 따른 자동 영구 삭제 없이 보관한다. 운영 전 보존 기간·영구 삭제·백업 정책을 별도로 정한다(DEC-157).
- 설비·품목이 soft delete되어도 기존 공정·검사·재고 변경 이력과 보고서를 보존하고 현재 권한에 따라 과거 조회를 제공한다. 신규 등록·생성 대상에서 삭제된 설비·품목을 제외한다(DEC-147).

공통 기준의 근거는 DEC-004다. 아래 기능별 완료 조건과 함께 적용한다.

## 3. 계정·인증·권한

### 로그인과 토큰

- 사번·비밀번호로 로그인한다. MVP 관리자·고용자 계정은 사전에 준비한다.
- 계정 생성 화면·API는 이번 프로젝트 범위에서 제외하고 관리자·고용자 계정을 DB 초기 데이터로 준비한다(DEC-063).
- 관리자는 기존 계정의 비밀번호를 임시 비밀번호로 초기화할 수 있다. 사용자는 임시 로그인 후 새 비밀번호로 변경하며 본인 비밀번호 변경을 지원한다.
- 초기 계정도 비밀번호 해시를 저장하고 실제 비밀번호는 저장소에 기록하지 않는다.
- 삭제된 계정까지 포함해 사번을 고유하게 유지한다. 작성자 계정이 soft delete되어도 보고서·작성자 연결·수정 및 다운로드 이력은 보존한다. 관리자는 작성자 활성 여부와 관계없이 기존 활성 보고서를 조회할 수 있다(DEC-146).
- 초기 계정 적재·비밀번호 변경·초기화에 공통 해시 생성 로직을 사용한다. 로그인 시 비밀번호 검증 라이브러리로 입력값과 저장된 해시를 검증한다(DEC-063). 알고리즘·라이브러리는 초기 구현 시 선정한다.
- JWT 기반 액세스·리프레시 토큰을 사용한다.
- 액세스·리프레시 토큰은 쿠키로 보관·전송한다(DEC-105). 인증 쿠키에 HttpOnly와 HTTPS 환경의 Secure를 적용하고 서버에 CSRF 방어를 적용한다(DEC-106). SameSite·Domain·Path·CORS와 구체적인 CSRF 방식은 배포 출처에 맞춰 설계한다. 보안 속성과 요청 흐름의 추가 설명은 후속 대화에서 제공한다.
- 액세스 토큰은 15분, 리프레시의 최대 기한은 최초 로그인부터 7일이다. 근무 종료 자동 로그아웃 시 해당 세션은 종료한다(DEC-119).
- 액세스 만료 시 유효한 리프레시 토큰으로 갱신하며 리프레시도 교체한다.
- 이전 리프레시는 폐기한다. 교체해도 최초 로그인부터 7일 기한을 유지한다.
- 폐기된 리프레시가 다시 제출되면 갱신을 거부하고 해당 세션의 현재 리프레시도 폐기해 재로그인을 요구한다. 다른 기기의 별도 로그인 세션은 유지한다. 기존 액세스 토큰은 원래 만료 시각까지 유효하다(DEC-107).
- 로그아웃 시 클라이언트 토큰과 해당 세션의 리프레시를 제거·폐기한다.
- 기존 액세스는 원래 만료 시각까지 유효하며, 남은 시간은 최대 15분이다.
- 유효기간은 환경 설정으로 관리한다. 만료·갱신 테스트에는 짧은 테스트용 값을 사용한다.
- 동일 계정에서 비밀번호를 5회 연속 틀리면 5분간 로그인 시도를 제한한다. 성공 시 연속 실패 횟수를 초기화하고 횟수·시간은 설정값으로 관리한다(DEC-111).
- 로그인 유지 체크박스는 제공하지 않는다. 근무 종료 전 수동 연장 또는 실제 작업에 따른 자동 연장이 없으면 자동 로그아웃한다(DEC-112를 DEC-180으로 보완). 자동 로그아웃 시 쿠키를 제거하고 해당 세션의 리프레시를 폐기한다. 기존 액세스는 원래 만료까지 최대 15분 유효하며 재로그인은 새 세션으로 처리한다(DEC-119).
- 사용자별 근무 종료 시각을 사용한다. 야근은 기본 1시간 연장하며 사용자가 종료 시각을 직접 지정할 수 있다. 기본 근무·야근 종료 모두 자동 로그아웃 10분 전에 알린다(DEC-113).
- 종료 10분 전부터 실제 입력·클릭 등 사용자 작업이 확인되면 종료 시각을 1시간 자동 연장하고 안내한다. AI 생성·자동 데이터 갱신만 진행 중인 경우에는 자동 연장하지 않는다. 수동 야근 버튼·종료 시각 지정과 연장된 종료 시각의 10분 전 알림을 유지한다. 기존 토큰 만료·폐기 정책은 유지한다(DEC-180).
- 연장된 종료 시각의 10분 전 구간에서도 실제 작업이 확인되면 다시 1시간 연장한다. 각 종료 예정 시각당 한 번만 적용하고 새 종료 시각을 안내한다. 작업이나 수동 연장이 없으면 종료 시각에 로그아웃한다. 최초 로그인 기준 리프레시 토큰 7일 상한은 유지한다(DEC-181).
- 같은 로그인 세션의 여러 탭은 서버 기준 종료 시각을 공유한다. 동시에 연장을 요청해도 해당 종료 예정 시각에 대한 자동 1시간 연장은 한 번만 적용한다. 별도 다중 탭 관리 화면은 만들지 않는다(DEC-182).
- 사용자별 기본 근무 시작·종료 시각은 계정과 함께 DB 초기 데이터로 준비한다. 근무표 등록·편집 화면과 외부 근태 시스템 연동은 추후 범위로 보류한다(DEC-116).
- 근무 종료로 자동 로그아웃된 후에도 사번·비밀번호로 재로그인할 수 있다(DEC-114). 재로그인 시 새 야근 종료 시각을 확인하며 기본값은 재로그인부터 1시간이다. 직접 변경과 종료 10분 전 알림을 적용한다(DEC-115).
- 화면을 닫거나 절전 후 복귀하면 서버 시각으로 이용 종료 여부를 확인한다. 종료됐다면 로그아웃 후 재로그인하며, 종료 10분 전 구간이면 남은 시간을 즉시 안내한다(DEC-117).

근거는 DEC-043, DEC-050~054다.

### 확정된 리소스별 권한

| 대상 | 관리자 | 고용자 |
| --- | --- | --- |
| AI 보고서 생성 | 가능 | 가능 |
| 보고 조회·검색 | 전체 보고 | 본인 보고 |
| 보고 수정·삭제 | 완료 여부와 관계없이 전체 보고 | 완료 전 본인 보고 |
| 보고 상태 변경 | 진행 중·완료로 변경, 완료에서 진행 중으로 복귀 | 불가 |
| 보고 다운로드 이력 | 조회 가능한 보고의 이력 | 조회 가능한 보고의 이력 |
| 대화 조회·검색·삭제 | 본인 대화 | 본인 대화 |
| 일정 등록 | 가능 | 가능 |
| 일정 조회 | 전체 일정 | 전체 일정 |
| 일정 수정·삭제 | 전체 일정 | 본인이 등록한 일정 |
| 공정·생산/검사·품질·완제품 재고 조회 | 전체 데이터 | 전체 데이터 |
| 공정·검사 기록 수정·삭제 | 가능, 변경 이력 보존 | 불가 |
| 공정·검사 기록의 수정·삭제 이력 조회 | 가능 | 불가 |

관리자용 ‘올라온 보고’ 화면은 목록·상세 조회를 제공하며 고용자 인터페이스는 별도로 존재한다. 백엔드는 두 역할에 AI 보고서 생성 권한을 부여하며, 관리자 화면에서 생성 기능을 제공할지는 미정이다(DEC-078).
다운로드 이력 권한은 DEC-025의 답변을 보고 조회 권한에 따르는 것으로 해석한 내용이다.
DEC-058에 따라 공정·생산/검사·품질·완제품 재고는 관리자와 고용자 모두 전체 조회하며 AI 조회에도 적용한다.
DEC-059·DEC-060에 따라 관리자와 고용자 모두 재고 변경을 등록할 수 있으며 즉시 수량에 반영한다. 고용자 등록 건은 관리자가 사후 확인한다.
DEC-158에 따라 관리자는 공정·검사 기록을 수정·삭제할 수 있다. 수정 전후 값·사유·작업자·시각을 기록하고 삭제는 soft delete로 처리한다. 해당 관리 기능을 MVP에 포함한다.
공정·검사 기록의 수정·삭제 이력은 관리자만 조회하며 서버에서 권한을 검사한다. 고용자는 수정된 현재 기록을 조회하고 soft delete된 기록은 일반 조회에서 제외한다(DEC-162).
공정·검사 기록의 수정·삭제에는 보고서와 같은 버전 검사를 적용한다. 먼저 저장된 변경을 덮어쓰지 않고 충돌을 안내하며, 작성 중인 입력은 화면에 유지해 최신 기록 확인 후 다시 수정할 수 있게 한다. 자동 병합·자동 재저장은 하지 않는다(DEC-178).
신규 공정 기록은 CSV 적재로 등록한다(DEC-159). 검사 결과는 자동 검사 시스템에서 유입되는 데이터이며 별도 수동 등록 화면은 제공하지 않는다. 실제 데이터·연동 확보 전에는 시연 데이터를 준비하고 시연 여부를 표시한다. DEC-159의 관리자 검사 수동 등록 합의는 DEC-161로 변경했다.
공정·검사 기록의 수정·삭제는 이후 조회·품질 집계·새 AI 조회 및 보고서 생성에 반영한다. 이미 생성한 보고서의 저장된 집계 스냅샷은 유지하며 최신 수치가 필요하면 새로 생성한다(DEC-160).

## 4. 기능별 요구사항

### 실시간 공정

- 제공된 과거 CSV를 서버에 적재하고 시연 순서에 따라 다음 레코드를 5초마다 반영한다.
- FE가 주기적으로 조회하여 시연 데이터를 표시한다.
- 설비별 생산 품목과 최근 사이클 시간을 표시한다. 작업 진행률은 필수 항목에서 제외한다.
- 데이터 기준 시각, 마지막 조회 시각, 시연 여부를 표시한다.
- 마지막 새 레코드 반영 후 15초간 새 레코드가 없으면 ‘갱신 지연’을 표시한다.
- 조회 실패는 ‘연결 오류’로 표시한다.
- 설비 상태 컬럼이나 값이 없으면 ‘상태 미확인’으로 표시한다.

확인한 공정 CSV 헤더에는 TimeStamp, EQUIP_CD, EQUIP_NAME, PART_NAME, Cycle_Time이 있다.
데이터 위치는 로컬 previous-workspace이며, 팀 공유·배포용 초기 데이터 제공 경로는 추가 정의해야 한다.
CSV 재생이 정상 종료되면 마지막 공정 값을 유지하고 ‘시연 종료’와 마지막 데이터 시각을 표시한다. 정상 종료는 갱신 지연·연결 오류와 구분하며 자동 반복 재생은 하지 않는다(DEC-166). 기존 화면의 진행률이나 정상·고장 예시는 확정 데이터로 간주하지 않는다.

근거는 DEC-005~007, Q-008이다.

### 올라온 보고

- 전체 보고 기능은 생성·조회·수정·삭제를 제공한다.
- 사용자가 생성 버튼을 누르면 AI가 보고서를 생성해 DB에 저장하고 ‘올라온 보고’ 목록에 등록한다. 이후 기존 역할·상태별 권한에 따라 수정할 수 있다(DEC-064·DEC-065). 생성 조건은 추가 확인한다.
- 이메일·메신저 전송은 추후 검토로 보류한다(DEC-065).
- 보고서 생성 대상은 작성자의 담당 범위를 기본값으로 사용하며 생성 전에 변경할 수 있다(Q-066). 담당 대상은 부서·생산 라인·설비가 될 수 있다. 복수 담당을 지원하고 담당 전체를 기본 선택한 뒤 필요한 대상을 남길 수 있다(DEC-067·DEC-068). 기존 조회 권한을 적용한다.
- 부서·라인과 소속 설비의 연결은 시연용 DB 초기 데이터로 제공한다. 부서·라인을 선택하면 연결된 CSV 설비의 기록을 집계하며, 여러 선택 대상에 포함된 설비는 한 번만 집계한다. 테이블 설계에 조직과 설비의 연결, CSV 설비 코드 매핑, 계정별 복수 담당을 반영한다(DEC-075).
- 우선 부서→복수 라인→복수 설비, 설비의 단일 현재 소속 라인을 설계 가정으로 사용한다. 실제 관계와 제약은 데이터셋을 검토한 뒤 조정한다(DEC-129).
- 계정별 복수 담당은 계정·근무시간과 함께 DB 초기 데이터로 준비한다. 담당 배정·변경 관리 화면은 추후 범위로 보류한다(DEC-130).
- 생성 종류는 일반·주간·월간이며 기본 기간은 오늘·이번 주·이번 달이다. 기간은 변경 가능하고 진행 중인 주·월은 현재까지 집계한다(DEC-069). 종류는 기존 보고 분류와 별도 개념으로 매핑을 설계한다.
- 주간 보고서의 ‘이번 주’는 한국 시간 기준 일요일부터 토요일까지다. 진행 중인 주는 생성 기준 시각까지만 집계하고 사용자 지정 기간을 유지한다(DEC-184).
- 월간 보고서는 한국 시간 기준 매월 1일부터 말일까지다. 진행 중인 달은 생성 기준 시각까지만 집계하고 사용자 지정 기간을 유지한다(DEC-185).
- 주간·월간 보고서는 사용자가 버튼을 눌러 생성하며 종류별 기본 기간을 제공한다. 정해진 시각의 예약 자동 생성은 추후 범위로 둔다(DEC-186).
- 관리자가 완료된 보고서를 수정해도 완료 상태는 유지한다. 상세 화면에 마지막 수정자·수정 시각을 표시하고 변경 이력에서 수정 내용을 확인하게 한다. 별도 재승인 단계나 새 승인 상태는 추가하지 않는다(DEC-187).
- 보고서의 대기·진행 중·완료 상태 변경 전후 상태·작업자·시각을 기록한다. 해당 보고서의 조회 권한이 있는 사용자가 상세 화면에서 확인하며 본문 수정 이력과 구분해 표시한다. 별도 승인 단계는 추가하지 않는다(DEC-188).
- 과거 CSV 시연 중에는 현재 재생 중인 데이터 시각을 기준으로 기본 기간을 계산한다. 화면에 시연 기준일을 표시하고 사용자가 생성 전에 기간을 변경할 수 있게 한다. 기본 기간의 주간·월간 보고서는 해당 재생 시각까지 집계한다(DEC-070).
- 선택한 기간·대상에 기록이 없어도 본문에 ‘조회된 기록 없음’을 표시해 등록한다. 일부 기록만 있으면 확인된 내용으로 작성한다. 미가동 여부는 상태나 가동 기록으로 확인된 경우에 표시한다(DEC-071).
- 데이터 조회 또는 AI 생성이 실패하면 오류를 안내한다. ‘올라온 보고’에는 등록하지 않으며, 선택한 조건을 유지해 사용자가 다시 시도할 수 있게 한다(DEC-072).
- 서버가 접수한 생성 작업은 화면 이동이나 새로고침 후에도 계속한다. 요청자는 ‘생성 중’ 상태와 완료·실패 결과를 다시 확인할 수 있다. 성공한 보고서는 ‘올라온 보고’에 등록한다(DEC-082).
- 수동·자동 로그아웃 후에도 이미 접수된 생성 작업은 계속하며 재로그인하면 상태와 결과를 확인할 수 있다. 작업 실행에는 서버의 현재 권한을 적용한다(DEC-118).
- 보고서 생성 상태는 실제 처리에 맞춰 접수·데이터 조회·본문 작성·완료 또는 실패·중단을 표시한다(DEC-095).
- 성공적으로 등록된 보고서는 ‘올라온 보고’에 표시하고, 생성 중·실패·중단 작업은 요청자의 ‘내 생성 작업’ 영역에 표시한다. 생성 단계와 보고서의 업무 상태를 구분한다(DEC-096).
- 요청자는 ‘내 생성 작업’에서 진행 중 생성을 취소할 수 있다. 취소가 확정되면 ‘취소됨’으로 표시하고 보고서를 등록하지 않는다. 완료·등록된 보고서는 기존 수정·삭제 권한을 따른다(DEC-127).
- 서버 중단으로 완료되지 못한 작업은 중단 상태를 안내하고, 조건을 유지해 사용자가 재시도할 수 있게 한다. 서버 복구 후 자동 재실행은 추후 범위로 보류한다(DEC-094).
- 생성 버튼을 누르면 서버의 접수 응답을 기다리는 동안 버튼을 비활성화한다. 서버는 동일한 요청 ID가 재전송되면 기존 작업 또는 결과를 반환한다. 접수 후 사용자가 ‘최신 데이터로 새로 생성’을 선택하면 새 요청 ID로 별도 작업을 접수한다(DEC-083).
- 일반·주간·월간 보고서의 공통 양식은 집계 기간과 대상, 생산·품질 요약, 기록에서 확인된 주요 이슈를 담는다. 시연 데이터를 사용한 보고서는 본문에 표시한다(DEC-073).
- 백엔드는 품질 리포트와 AI 보고서에 공통 집계 규칙을 적용한다. AI 본문, 표, 그래프는 같은 보고서 집계 결과를 사용한다. 구현 기본안은 Markdown 표와 Matplotlib 그래프를 화면과 PDF에 포함하는 것이며, Seaborn은 필요한 차트에 검토한다(DEC-079).
- AI 본문 작성에는 기간·대상·기준 시각, 서버 집계 수치, 필요한 이슈 근거와 시연·누락 정보를 전달한다. 상세 분석에 필요한 기록은 추가 제공하며 표·그래프는 저장된 집계 결과로 서버에서 만든다. 실제 전송 필드와 팀 승인 기준은 추가 확인한다(DEC-128).
- 보고서 생성 시 집계 기간·대상·수치를 함께 저장한다. 기존 보고서 화면과 PDF의 표·그래프는 저장된 집계 결과를 사용한다. ‘다시 생성’은 현재 데이터로 새 보고서를 등록한다(DEC-080).
- 서버는 생성 요청을 접수할 때 집계 기준을 고정한다. CSV 시연에서는 접수 당시 재생 중인 데이터 시각을 사용한다. 지정된 기간에서 해당 시점까지 조회 가능했던 데이터만 집계하고, 이후 들어온 데이터는 새로 생성한 보고서에 반영한다. 기준 시각은 저장하고 상세 화면과 PDF에 표시한다(DEC-084).
- 수정 권한이 있는 사용자는 제목과 본문을 편집할 수 있다. 집계 기간·대상과 자동 표·그래프의 수치는 생성 당시 값으로 유지한다. 집계 조건이나 수치를 바꾸려면 새 보고서를 생성한다(DEC-081).
- 종류·집계 기간·대상이 같은 조회 가능한 활성 보고서가 있으면 생성 전에 안내한다. 사용자는 기존 보고서를 열거나 현재 데이터로 새 보고서를 생성할 수 있다. 수정 권한이 있으면 안내에서 기존 보고서 편집으로 이동해 같은 보고서에 저장할 수 있으며 수정 이력을 남긴다. 다시 생성하더라도 기존 보고서는 보존한다(DEC-074).
- 작성 필수값은 제목·내용·분류이며 관련 설비는 선택이다.
- 위 필수값은 저장되는 보고 데이터의 기준이다. 버튼 기반 생성에서 사용자가 직접 입력할 항목과 AI가 채울 항목은 생성 조건 설계에서 정한다.
- 분류는 설비 이상·품질 보고·점검 완료·기타·정기보고이며 정기보고는 주간·월간으로 구분한다.
- 제목·내용 검색과 분류·상태·작성 기간 필터를 제공한다.
- 등록 시 상태는 ‘대기’다. 관리자에 의해 ‘진행 중’ 또는 ‘완료’로 변경할 수 있다.
- 관리자는 ‘완료’를 ‘진행 중’으로 되돌릴 수 있다. 변경자·시각·이전 상태를 보존한다.
- 관리자가 완료 보고서의 제목·본문을 수정해도 완료 상태는 유지한다. 수정 이력을 남기고 재처리가 필요하면 관리자가 직접 진행 중으로 되돌린다(DEC-110).
- 수정 시 이전 내용·수정자·수정 시각을 보존한다.
- 보고서별 버전 번호로 동시 수정 충돌을 검사한다. 저장 시 열었던 버전과 현재 버전을 비교하고 일치할 때 수정·버전 증가·이력 기록을 같은 트랜잭션에서 처리한다. 불일치하면 작성 중인 내용을 유지하고 충돌을 안내한다. 수정 이력에 버전을 연결한다(DEC-137).
- 수정 이력은 해당 보고서를 현재 조회할 수 있는 사용자에게 제공한다. 상세 화면의 수정 이력 버튼에서 버전·수정자·시각 목록을 열고, 버전 선택 시 당시 제목·본문을 읽기 전용으로 확인한다. 현재 보고서로 돌아갈 수 있다(DEC-138).
- 삭제 시 삭제 표시를 남기고 일반 목록에서 숨긴다.
- 본문 원본은 Markdown 텍스트로 DB에 저장한다.
- PDF 다운로드 요청 시 변환하며 생성 PDF를 서버에 영구 보관하지 않는다.
- 보고서별 다운로드 사용자·시각·횟수를 기록한다.
- 다운로드 이력에 보고서 버전도 기록한다. PDF는 해당 버전의 본문과 저장된 집계 수치로 생성한다(DEC-140).
- 수정 이력에서 이전 버전을 조회할 때도 해당 버전 PDF 다운로드를 제공한다. 현재 보고서 조회 권한을 검증하고 다운로드 이력에 해당 버전을 기록한다(DEC-141).
- PDF 생성 성공 후 다운로드 응답을 제공한 요청을 1회로 집계한다. 재다운로드도 매번 기록한다.
- 생성 실패는 집계에서 제외한다. 집계는 기기의 실제 저장 완료를 의미하지 않는다.

최신 범위의 근거는 DEC-010~020, DEC-022~025다.
DEC-009·012의 화면 범위는 DEC-013으로 보완되었고, DEC-021의 파일 중심 안은 Markdown 기반 제공 방식으로 구체화되었다.
보고서의 별도 첨부파일 업로드는 MVP에서 제외하고 추후 범위로 둔다. Markdown 본문·서버 생성 표·그래프와 PDF 다운로드는 유지한다. 첨부파일 도입 시 형식·용량·권한·저장 방식을 정한다(DEC-169). md2pdf는 참고 자료이며 변환 도구 채택은 미정이다.
제목·문단·목록·표·강조·코드 블록 등 기본 Markdown을 지원한다. 본문에 넣은 HTML·스크립트와 임의의 외부 이미지 로딩은 허용하지 않는다. 서버 생성 그래프는 화면과 PDF에 포함한다. 현재 범위에 S3 등 외부 스토리지 도입을 추가하지 않는다(DEC-170).
그래프는 저장된 집계 스냅샷으로 화면 조회·PDF 다운로드 시 서버에서 생성하고 이미지 파일은 영구 보관하지 않는다. 루트 [DESIGN.md](../../DESIGN.md)의 색상·글꼴·가독성 기준을 참고한 공통 스타일을 화면과 PDF에 적용한다. Primary #635B85, 정상 #61E2A6, 주의 #F2BB69, 오류·위험 #D95F70 등 상태 색상 의미를 유지하고 텍스트·범례를 함께 제공한다. 차트별 색상 매핑·글꼴·축·범례·단위·여백을 공통 설정으로 관리하며 보고서마다 AI가 임의로 디자인을 바꾸지 않는다. 렌더링 환경에서 한글 글꼴과 화면·PDF 가독성을 확인한다(DEC-171).
그래프만 생성에 실패하면 화면과 PDF에서 본문·수치 표는 제공하고 해당 위치에 누락 안내와 확인 가능한 실패 사유를 표시한다. 사유는 이해하기 쉬운 표현으로 안내하며 내부 스택·파일 경로·비밀값을 노출하지 않는다. 원인을 확인할 수 없으면 원인 확인이 필요하다고 안내한다. 상세 오류와 요청 ID는 서버 로그에 남긴다. PDF 자체 생성 실패는 다운로드 실패로 처리하고 성공 횟수에 포함하지 않는다(DEC-172).
그래프 생성 실패 시 화면에 ‘다시 시도’를 제공하고 동일한 저장 집계로 그래프만 다시 생성한다. PDF 재다운로드에서도 같은 저장 집계를 사용하며 본문·수치·보고서 버전은 유지한다(DEC-173).
AI 본문 작성 실패 등으로 실패한 작업의 미완성 보고서는 목록에 등록하지 않는다. ‘내 생성 작업’에 실패 사유와 생성 조건을 남긴다. 재시도는 같은 조건으로 새 작업을 접수하며 새 접수 시점의 데이터 기준으로 생성한다. 기존 실패 이력은 유지한다(DEC-174).
AI 답변·보고서 생성의 전체 처리 시간 상한과 시간 초과 정책은 실제 모델로 소요 시간을 측정한 뒤 정한다(Q-175 보류). 화면 이동·새로고침 후에도 서버에서 생성을 계속하고 상태·결과를 다시 확인하는 기존 합의는 유지한다. SQL 쿼리당 5초 제한과 구분한다.
다른 화면을 보는 동안 AI 답변·보고서 생성이 완료되면 앱 안에서 완료 안내와 ‘결과 보기’ 버튼을 제공한다. 이메일·메신저·브라우저 푸시는 추후 범위다. 앱을 닫았다가 돌아오면 기존 대화 또는 ‘내 생성 작업’·보고서 목록에서 상태·결과를 확인한다. 결과 접근에는 현재 권한을 적용한다(DEC-176).
다른 화면에서 AI 생성이 실패·중단되면 앱 내 안내와 ‘작업 확인’ 버튼을 제공한다. 현재 화면은 자동으로 이동하지 않으며 사용자가 버튼을 눌러 해당 대화·작업에서 사유 확인과 기존 규칙에 따른 재시도를 진행한다(DEC-177).

### 생산·검사 이력

- 공정 데이터는 제공 CSV를 활용한다.
- 실제 생산 수량과 집계 기준을 확인하기 전에는 CSV 행 수를 ‘생산 기록 건수’로 표시한다. 실제 생산량은 수량 데이터와 집계 기준 확인 후 제공하며 검사 건수·재고 수량과 구분한다(DEC-190).
- 같은 CSV를 다시 적재해도 이력과 집계 건수가 늘어나지 않는다. 같은 원본 식별자에 다른 내용이 들어오면 기존 기록을 보존하고 충돌을 알린다. 식별자와 유일성 범위는 기준 CSV 확인 후 정한다(DEC-076).
- 별도 검사 데이터는 현재 미확보이며 임의의 시연 데이터를 사용한다.
- 기간·설비·품목·검사 결과로 목록을 필터링한다.
- 개별 기록의 공정 수치·검사 결과·불량 사유를 상세 조회한다.
- 검사 데이터의 시연 여부를 표시한다.
- 실제 검사 데이터 확보 후 같은 조회 기능에 연동할 수 있게 구현한다.

근거는 DEC-026~027이다. CSV의 라벨 컬럼 존재만으로 실제 검사 연동이 확보된 것으로 취급하지 않는다.

### 품질 리포트

- 시연용 검사 데이터로 기간·설비·품목별 지표를 조회한다.
- 검사 건수, 양품·불량 건수, 불량률, 불량 유형별 분포를 제공한다.
- 검사 기록 1건을 집계 단위로 한다.
- 불량률은 불량 판정 건수 ÷ (양품 판정 건수 + 불량 판정 건수) × 100이다.
- 판정 기록이 없으면 불량률은 ‘—’로 표시한다.
- 검사 시연 데이터에 양품·불량 판정과 시연용 불량 유형을 미리 넣고 해당 값으로 집계한다. 불량 판정이지만 유형이 없는 기록은 ‘미분류’로 집계한다. 실제 자동 검사 판정 기준과 유형 매핑은 데이터 확보 후 정한다(DEC-165).
- 시연 데이터 여부를 표시한다.

근거는 DEC-028~029다.
- 가동률도 임의의 시연 데이터로 제공하고 실제 측정값과 구분되도록 시연 여부를 표시한다. 실제 가동률 데이터 연동은 추후 범위다(DEC-163).
- 설비별·일자별 계획 가동 시간과 실제 가동 시간을 시연 데이터로 준비한다. 가동률은 `실제 가동 시간 ÷ 계획 가동 시간 × 100`이다. 기간·설비별 조회는 두 시간을 각각 합산한 후 계산하며 계획 가동 시간 합계가 0이면 ‘—’로 표시한다. 화면·AI 답변·보고서에 시연 데이터임을 표시한다(DEC-164).

### AI 대화·이력·검색

- 실제 AI가 자연어 요청을 조회 쿼리로 변환하고 공정·보고·생산·검사·품질 정보를 조회해 답변한다.
- 대화 처리 중 실제 단계에 맞춰 데이터 조회 중·답변 작성 중을 표시한다(DEC-095).
- MVP의 대화 답변은 완성 후 한 번에 표시한다. 단순 답변 스트리밍은 추후 검토한다(DEC-123).
- 조회·답변 생성에 실패하면 사용자 질문을 유지하고 다시 시도를 제공한다. 재시도 결과는 같은 질문의 답변 영역에 표시한다(DEC-124).
- 같은 대화에서 생성 중 다음 질문 작성은 허용하며 전송은 완료·실패·취소 후에 허용한다. 생성 취소와 질문 수정 후 재전송을 제공한다(DEC-125).
- 취소한 요청의 늦은 결과가 새 답변에 섞이지 않도록 요청별 상태를 관리한다. 취소된 결과는 사용자 답변·후속 대화 맥락에 추가하지 않고 가능한 범위에서 서버의 조회·AI 호출 취소를 전파하는 구현 기본안을 적용한다.
- 화면 이동·새로고침 후에도 대화 답변 생성을 계속하며 돌아오면 답변이나 실패 상태를 확인할 수 있다. 직접 취소한 요청은 취소 처리 기준을 적용한다(DEC-126).
- 답변에 조회 기간·대상·집계 기준 시각과 시연 여부를 표시한다. 근거 보고서·이력은 조회 권한이 있는 상세 화면으로 연결한다(DEC-097).
- 과거 답변과 조회 기준을 보존한다. ‘최신 데이터로 다시 조회’하면 같은 대화에 새 답변을 추가하며, 근거 링크 접근 시 현재 권한과 삭제 상태를 검증한다(DEC-098).
- 근거 데이터의 현재 조회 권한이 없으면 해당 내용을 포함한 과거 AI 답변을 가리고 ‘현재 권한으로 볼 수 없는 답변입니다’로 표시한다(DEC-099).
- 근거가 soft delete된 과거 답변은 현재 권한을 확인한 뒤 ‘작성 당시 자료이며 근거가 삭제됨’을 표시해 참고용으로 제공한다. 권한이 없는 내용은 가린다. 최신 재조회에는 현재 권한과 삭제 필터를 적용한다(DEC-100).
- 후속 질문에는 현재 권한이 있는 과거 답변을 작성 시각·근거 삭제 상태와 함께 전달해 과거 참고 자료로 사용한다. 현재 상황은 현재 데이터로 다시 조회하고 권한이 없는 내용은 AI에 전달하지 않는다(DEC-101).
- 보고 조회에는 기존 역할별 조회 권한을 적용한다.
- 명확한 오타는 해석하며 조회 대상·기간 등 의미가 모호하면 사용자에게 확인한다.
- SQL 문법·컬럼 참조 오류는 AI가 1회 수정 후 재시도한다. 재실패하면 조회 실패를 안내한다.
- 권한 위반은 즉시 차단하고 조회 결과가 없으면 해당 조건의 데이터가 없다고 답한다.
- 상세 조회는 기본 10건·페이지당 최대 100건이며 같은 조건으로 다음 결과를 요청할 수 있다(DEC-122).
- 통계는 요청 범위 전체를 DB에서 집계한다. 상세 페이지 제한을 통계 분모에 적용하지 않는다.
- SQL 실행은 우선 쿼리당 5초로 제한한다. 초과하면 조건·기간을 좁히도록 안내하고 성능 검증 후 조정한다.
- 대화방 제목·사용자 질문·AI 답변·대화 시각을 저장한다.
- 제목·질문·답변 키워드 검색과 기간 필터를 제공한다.
- 본인 대화만 조회·검색하며 자동 만료 없이 보관한다. 본인 대화방 삭제를 지원한다.
- 삭제는 soft delete로 처리하고 해당 방의 질문·답변도 일반 조회·검색·AI 조회에서 제외한다(DEC-062).

근거는 DEC-030, Q-031, DEC-032~034, DEC-055~057이다.
DEC-061에 따라 AI에 필요한 업무 테이블·컬럼만 공개하고 비밀번호 해시·인증 토큰은 제외한다.
서버에서 SQL과 로그인 사용자별 조회 범위를 검증하며, AI 조회용 DB 계정은 필요한 읽기 권한만 가진다. 사용자별 조회 범위도 DB에서 강제한다.
RLS·제한된 뷰·함수 등의 구체적인 강제 방식과 우회 방지 검증, AI 제공자·모델은 구현 전 추가 설계 대상이다.

### 일정 상세

- 종일 일정과 시간 지정 일정을 지원한다. 종일 일정은 한국 기준 날짜로 처리하고 시간 지정 일정은 한국 시간 기준으로 입력한다. 시간 지정 일정의 종료가 시작보다 뒤인지 FE·BE에서 검증한다. 시간 지정 값의 API 전달·저장은 기존 UTC 계약을 따른다(DEC-168).

- 달력·목록·상세 조회와 CRUD를 제공하며 3절의 권한을 적용한다.
- 기본 CRUD를 우선한다. 반복·복사는 낮은 우선순위이며 필수 포함 여부는 보류다.
- 세부 입력값은 구현 시 기본안을 적용할 수 있다.

구현 기본안은 제목·유형·시작·종료 시각 필수, 상세 내용 선택, 유형은 점검·생산·회의·기타다.
이는 AI가 정리한 기본안이며 개별 입력값에 대한 사용자 확정과 구분한다.
근거는 DEC-035~037, Q-038~039, DEC-040이다.

### 인수인계 노트

- 관리자는 전체 노트, 고용자는 본인 노트만 soft delete할 수 있다(DEC-108).

- 홈 인수인계 노트를 DB에 저장하고 공유한다.
- 관리자·고용자 모두 작성·조회할 수 있으며 본인 노트를 수정할 수 있다.
- 인수인계 본문 수정은 작성자 본인만 가능하며 관리자도 타인의 본문은 수정할 수 없다. 서버에서 작성자 권한을 검사한다. 관리자의 전체 조회·삭제 권한과 사용자별 확인 표시는 유지한다(DEC-183).
- 읽은 사용자의 확인 표시를 제공하고 확인자·확인 시각을 기록한다. 본문 수정 시 수정 시각을 표시하며, 수정 후 재확인을 필수로 요구하지 않는다. 중요한 추가 내용은 새 노트로 남긴다(DEC-090·DEC-091).
- 작성자의 담당 범위를 기본 대상으로 지정하고 조정할 수 있다(DEC-092). 관리자·고용자 모두 전체 노트를 조회할 수 있다. 고용자의 기본 목록은 본인 담당으로 필터링하며 필터를 바꿔 다른 담당과 전체 노트를 볼 수 있다(DEC-109).

### 재고 관리

- 설비·품목 기본정보는 데이터셋과 DB 초기 데이터로 준비한다. 별도 기본정보 등록·편집 관리 화면은 추후로 보류한다. 입출고·조정·정정과 최소 재고 기준 관리 기능은 제공한다(DEC-149).

- 관리 대상은 완성된 제품이다.
- 생산·검사 기록 추가만으로 완제품 재고를 자동 증가시키지 않는다. 생산에 따른 입고는 사용자가 입고를 등록했을 때 반영하며 초기 수량·조정·정정 등 기존 원장 규칙은 유지한다. 자동 입고 연동은 실제 수량 데이터와 업무 기준 확인 후 추후 검토한다(DEC-201).
- 시연 데이터로 제품별 현재 수량 조회, 입고·출고·조정 등록과 변경 이력 확인을 제공한다.
- 관리자·고용자 모두 변경을 등록할 수 있으며 고용자 등록 건은 관리자가 추가 확인한다(DEC-059).
- 변경 등록 즉시 수량에 반영하고 관리자가 사후 확인한다(DEC-060).
- 폐기는 기존 수량 조정으로 감소분과 사유를 기록하는 구현 기본안으로 간소화한다. 기존 권한·사후 확인·음수 차단·이력 규칙을 적용한다(DEC-150).
- 잘못 등록한 재고 변경은 원래 기록을 보존한다. 원래 기록에 연결된 별도 정정 이력에 사유와 정정 수량을 남기고, 정정 수량을 현재고에 즉시 반영한다(DEC-085).
- 관리자는 모든 재고 변경을, 고용자는 본인이 등록한 변경만 정정할 수 있다. 고용자 정정도 즉시 반영하며 관리자가 사후 확인한다. 정정 사유·등록자·원래 기록을 이력으로 남긴다(DEC-086).
- 고용자의 본인 기록 정정은 관리자 확인 전까지 허용하고 확인 후에는 관리자만 정정할 수 있다. 확인 완료 여부·확인자·확인 시각을 기록한다(DEC-088).
- 완제품 수량은 정수 ‘개’ 단위다. 출고·조정·정정으로 현재고가 0 미만이 되는 요청은 차단한다. 실제 수량과 시스템 수량의 차이는 사유를 남긴 조정으로 맞춘다(DEC-087).
- 품목별 최소 재고 수량을 설정하고 현재고가 그보다 적으면 목록에 ‘재고 부족’을 표시한다. 기준이 없는 품목에는 경고를 표시하지 않는다(DEC-089).
- 최소 재고 수량은 관리자만 설정·변경하고 고용자는 기준값과 부족 여부를 조회한다(DEC-131).
- 현재고가 남은 품목은 삭제를 차단한다. 출고·조정으로 수량을 0으로 정리한 뒤 soft delete하며 수량 정리에도 사유와 변경 이력을 남긴다(DEC-148).
- 초기 수량과 입고·출고·조정·정정 이력을 현재고의 기준으로 삼는다. 현재 수량을 별도 보관할 경우 이력과 같은 트랜잭션에서 갱신하며 이력 합계로 검증할 수 있게 한다(DEC-139).

근거는 DEC-041이다.

## 5. 기술·개발·검증 기준

기본 자동 테스트는 AI 응답 대역을 사용해 AI API 키·호출 비용 없이 실행한다. 권한·쿼리 검증·실패·취소 등 서버 규칙은 실제 서버 코드로 검증한다. 실제 모델 호출은 키가 있는 개발자가 별도 선택 실행하는 통합 점검으로 분리해 응답 형식·소요 시간·보고서 품질을 확인한다. 응답 대역 테스트 통과를 실제 모델 연동 완료로 보고하지 않는다(DEC-193).
자동 테스트의 데이터 초기화는 명시한 별도 테스트 DB에서만 허용한다. 테스트 DB 설정이 없거나 개발 DB와 같으면 실행을 중단하며 개발 DB로 자동 연결하지 않는다. 구체적인 DB 식별·검증 방식은 초기 구성에서 구현한다(DEC-194).
초기 계정·조직·설비·품목 데이터 적재는 서버 시작 시 자동 실행하지 않고 별도 명령으로 제공한다. 재실행 시 중복 생성하지 않고 기존 비밀번호·수정값을 임의로 덮어쓰지 않는다. 초기 구성 시 BE/README에 실행 방법을 안내한다(DEC-195).
기본 초기 데이터 적재 중 오류가 나면 해당 실행의 DB 변경을 모두 롤백하고 실패 항목을 안내한다. 수정 후 같은 명령을 재실행할 수 있게 한다. 대용량 공정 CSV 적재의 배치·오류 처리는 기준 CSV 확인 후 별도로 정한다(DEC-196).
마이그레이션 파일은 검토·테스트 후 서버 시작과 분리된 단계에서 한 번 적용한다. 로컬에서는 명령으로 적용하고 초기 구성 시 BE/README에 적용·현재 버전 확인 절차를 안내한다. 배포 자동화는 배포 환경 확정 후 정한다. 공유·적용된 파일은 수정하지 않고 후속 파일을 추가하며 운영 DB 적용은 명시적 승인을 유지한다(DEC-197).
서버 시작 시 DB 마이그레이션 버전을 확인한다. 미적용 변경이 있으면 시작을 중단하고 ‘마이그레이션 적용 필요’와 적용 절차를 안내한다. 자동 스키마 변경은 하지 않으며 적용 후 재실행한다. 팀원이 최신 코드를 받은 뒤 DB 적용을 놓쳐 요청 처리 중 컬럼 누락 오류를 겪는 일을 조기에 발견하기 위한 정책이다. 초기 구성 시 BE/README에 증상·원인·적용·버전 확인·재실행 절차를 안내하고 미적용 시 시작 실패·적용 후 정상 시작을 검증한다. 상세 질문·설명·결정 배경은 [DEC-198](DECISION_HISTORY.md#dec-198--미적용-마이그레이션이-있으면-서버-시작-중단-q-198)에 보존한다.

DB 접속 정보·JWT 서명 키 등 필수 설정 누락·형식 오류는 서버 시작 단계에서 명확한 설정 오류로 중단하고 임시 비밀값으로 자동 대체하지 않는다. AI API 설정만 누락된 경우 일반 기능은 실행하고 AI 기능에는 설정 필요를 안내한다. 비밀값은 오류 메시지·로그에 노출하지 않는다. 설정 형식 검증과 외부 서비스 실제 접속·인증 오류는 구분한다(DEC-191).
초기 BE 구성 시 .env.example에 안전한 예시를 제공하고 팀원이 복사해 개인 .env를 만들도록 한다. BE/README에 설정 방법·필수/선택 항목을 안내하고 AI 설정은 생략 가능하다고 명시한다. 실제 비밀값과 .env는 Git에 포함하지 않는다. 이는 초기 구성 요구사항이며 실행 가능한 파일 작성 완료를 의미하지 않는다(DEC-192).

DB 내부 기본키는 자동 증가 bigint를 기본으로 한다. 사번·설비 코드는 별도 고유 필드로 관리하며, 초기 데이터는 해당 업무 식별자로 내부 ID를 찾아 연결한다. 세부 유일성 범위는 테이블 설계와 데이터셋에서 검증한다(DEC-143).
테이블·컬럼명은 소문자 snake_case로 작성하고 테이블명은 단수형으로 통일한다(DEC-144).
업무 리소스에는 created_at·updated_at, soft delete 대상에는 deleted_at을 둔다. 삭제 전 deleted_at은 NULL이며 삭제 시각을 기록한다. 일반 조회는 삭제 전 데이터를 대상으로 하고 과거 AI 답변의 근거 삭제 표시는 DEC-100을 따른다(DEC-145).

공통 개발 브랜치는 dev다. 작업 브랜치는 최신 dev에서 분기하고 MR 대상은 dev로 지정한다(DEC-133). 브랜치 이름은 별도 결정한다.

| 항목 | 합의 내용 |
| --- | --- |
| 백엔드 | Python, FastAPI |
| DB 접근·마이그레이션 | SQLAlchemy, Alembic |
| 영속 저장소 | PostgreSQL |
| 패키지 관리 | venv + pip, requirements.txt 버전 고정 |
| 로컬 실행 | 로컬 Python 앱 + Docker PostgreSQL |
| 코드 검사 | Ruff 린트·포맷, mypy 기본 타입 검사 |
| 테스트·입력 검증 | pytest, FastAPI의 Pydantic |

신규·수정 함수에 타입 힌트를 작성하며 MR 전과 CI에서 합의한 검사를 실행한다.
권한·AI 쿼리 권한·CRUD 업무 규칙·통계 계산을 주요 검증 대상으로 한다.
DB 연동 테스트는 개발 DB와 별도의 테스트용 PostgreSQL에서 시나리오별 초기 데이터로 실행한다. 로그인·권한·재고 변경·보고서 등록·중복 요청·AI 조회 권한을 실제 PostgreSQL 기준으로 검증한다(DEC-132).
의존성 설치·검증 명령·CI는 실제 초기 구성 후 문서화한다.
개발 기준은 Python 3.14와 PostgreSQL 18이다. 초기 설치·통합 검증 후 패치 버전을 고정하고 팀원·CI·개발·테스트 환경의 버전 계열을 맞춘다(DEC-142).
근거는 Q-042의 확정 답변, DEC-045~046, DEC-048이다.
Router·Service/Domain·Repository의 책임과 생성자 주입은 AGENTS.md 기준을 따른다.

## 6. FE·BE 공통 API 계약

API_SPEC.md의 계약과 FastAPI OpenAPI 문서를 함께 관리한다. 팀원의 작성·확인·검증·MR 절차는 [API_DOCUMENTATION_GUIDE.md](API_DOCUMENTATION_GUIDE.md)를 따른다(DEC-153).
호환성이 깨지는 변경은 새 규격 추가 → FE 전환 확인 → 기존 규격 제거 순서로 적용한다. 작은 내부 변경은 FE·BE가 적용 시점을 합의한다(DEC-154).

서버 관리 로깅은 AI 작업을 포함한 요청 처리·오류·인증·서버 상태를 추적하도록 적용한다(DEC-121). 구현 기본안은 공통 로거, 요청 ID, 요청 경로·메서드, 응답 상태·처리 시간, 예외 원인과 인증·시작/종료 이벤트 기록이다. 비밀값·쿠키·대화 본문·원본 개인정보는 일반 로그에서 제외한다. 설정과 사용 예시는 초기 구성에 포함하며 저장 위치·보존 기간·수집 도구는 배포 환경에 맞춰 정한다.

AI 조회·보고서 생성에 요청자 식별자, 작업 종류, 시작·종료 시각, 처리 결과와 오류 코드를 기록한다. 일반 로그에는 비밀번호·토큰·원본 개인정보·대화 본문을 기록하지 않으며, 대화는 권한이 적용된 대화 저장소에서 관리한다. 로그 추가 요구사항은 후속 논의한다(DEC-102).

DEC-152에서 다음 공통 기본안에 FE·BE가 합의했다. 상세 계약은 [API_SPEC.md](API_SPEC.md)에서 관리한다.

- API 기본 경로 /api/v1
- JSON 필드 snake_case
- UTC 저장·RFC 3339 전송과 한국 시간 표시
- 오류 응답은 HTTP 상태 코드와 code·message·request_id를 반환한다. 필드별 오류 정보는 입력 검증 실패 시 선택적으로 포함한다(DEC-103·DEC-152).
- 성공 응답은 단건 데이터 객체, 목록의 items와 페이지 정보, 보고서 생성 접수의 작업 ID와 처리 상태를 반환한다(DEC-104·DEC-152).

개별 API와 성공·오류 응답 필드는 API_SPEC의 기술 기본안을 바탕으로 FE 상세 검토한다. 부분 수정의 생략·null 규칙은 DEC-155에서 확정했다. 페이지네이션은 페이지 번호·페이지 크기 기반 offset 방식이며 기본 10개·최대 100개다(DEC-122·DEC-152).
CSV 원본 시간대는 확인이 필요하다. 일정의 날짜 전용 값은 한국 기준 날짜이며 시간 지정과 구분한다(DEC-168).

## 7. 검증 시나리오 초안

핵심 데모는 고용자 로그인 → 담당 공정·품질 확인 → 자연어 조회 → AI 보고서 생성 → 관리자 목록 조회·확인이다. 재고·일정·인수인계·근무 종료 알림·야근 연장은 개별 시연으로 확인한다(DEC-135).
최종 CSV를 정한 뒤 검사·재고 시연 데이터를 같은 품목·설비·기간에 맞춰 준비한다. 시연 데이터 여부를 표시하고 재고 수량이 생산 기록 건수와 같다고 가정하지 않는다(DEC-136).
아래 기능별 검증 항목은 요구사항에서 도출한 초안이며, 구체적인 입력 데이터와 시연 절차는 이후 확정한다.

| 기능 | 검증할 공개 동작 |
| --- | --- |
| 공정 | CSV 재생 → 품목·사이클 갱신 → 지연·연결 오류 표시 |
| 보고 | 고용자 작성 → 관리자 조회·상태 변경 → 완료 후 작성자 수정 거부 → PDF 다운로드 이력 |
| 검사 | 시연 기록 적재 → 조건 필터 → 상세 확인 |
| 품질 | 조건별 양품·불량 집계 → 불량률 확인 → 판정 없음 표시 |
| AI | 자연어 조회 → 권한 범위 결과 → 다음 페이지 → 오류 재시도·접근 차단 |
| 대화 | 저장 → 본인 이력 검색 → 타인 이력 접근 거부 → 본인 삭제 |
| 일정 | 등록 → 전체 공개 → 작성자·관리자 수정 → 타 고용자 수정 거부 |
| 재고 | 시연 제품 조회 → 입출고·조정 → 현재 수량과 이력 확인 |
