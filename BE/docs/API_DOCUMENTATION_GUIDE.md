# 팀 API 문서 작성·확인 가이드

2026-11-19 기준이다. [API_SPEC.md](API_SPEC.md)의 FE·BE 계약을 구현하고 확인하는 절차를 안내한다.
문서화 방식은 DEC-153에 따라 Markdown 계약 문서와 FastAPI의 OpenAPI 문서 화면을 함께 사용한다.

## 현재 준비 상태

현재 BE에는 기획 문서만 있다. FastAPI 앱·의존성 파일·실행 명령과 개별 API는 초기 구성 단계에서 추가한다.
따라서 이 가이드의 문서 화면 절차는 백엔드 서버를 실행할 수 있게 된 뒤 사용한다.
초기 구성 담당자는 BE/README.md에 실제 설치·DB 준비·실행 명령과 서버 주소를 기록한다. 팀원은 해당 명령으로 실행한다.

## 문서별 역할

| 문서·화면 | 확인할 내용 | 갱신 방식 |
| --- | --- | --- |
| REQUIREMENTS.md | 업무 규칙·권한·합의한 동작 | 합의 변경 시 수정 |
| API_SPEC.md | API 경로·메서드·필드·상태 코드·예시 | FE·BE 합의와 구현 변경 시 수정 |
| /docs | Swagger UI에서 구현한 API의 구조 확인·호출 | FastAPI 코드의 선언에서 자동 생성 |
| /redoc | 읽기 중심으로 API 구조 확인 | 같은 OpenAPI 명세에서 생성 |
| /openapi.json | 도구와 테스트가 읽을 API 스키마 | FastAPI 코드의 선언에서 자동 생성 |

Markdown 계약은 담당자가 갱신한다. API 코드의 모델·설명·응답 선언은 자동 문서에 반영된다.
실제 예외 응답과 업무 규칙은 선언·테스트·리뷰를 함께 확인한다.
문서 화면 경로는 기본 설정이며, API 리소스의 기본 경로인 /api/v1과 구분해서 사용한다.

기본 문서 화면과 OpenAPI 자동 생성은 [FastAPI 공식 첫 단계 가이드](https://fastapi.tiangolo.com/tutorial/first-steps/)에서 확인할 수 있다.

## 1. API 계약부터 작성하기

BE 담당자는 API_SPEC.md의 해당 영역에 아래 표를 채운다. FE 담당자는 호출에 필요한 정보가 있는지 검토한다.

| 항목 | 작성할 내용 |
| --- | --- |
| 목적 | 어떤 사용자 동작을 처리하는지 |
| 경로·메서드 | /api/v1 기준 경로와 HTTP 메서드 |
| 권한 | 로그인 필요 여부·역할·소유권·상태별 제한 |
| 경로·쿼리 필드 | 이름·타입·필수 여부·기본값·허용값 |
| 요청 본문 | 각 필드의 타입·필수 여부·null 허용·검증 기준 |
| 성공 응답 | HTTP 상태 코드·필드·예시 |
| 실패 응답 | 상황별 HTTP 상태 코드·업무 오류 코드·예시 |
| 상태 변경 | DB 변경·버전·이력·트랜잭션·작업 상태 |
| 특수 처리 | 페이지·중복 요청·취소·시연 표시·시간 기준 |

‘필드 생략 가능’과 ‘값으로 null 허용’을 각각 적는다. 요청과 응답 양쪽에 적용한다.
FE는 해당 작업의 필수값을 전송 전에 검사해 입력 오류를 안내한다. BE도 같은 계약으로 요청을 검증한다. 부분 수정은 필드 생략의 의미를 따로 확인한다.
계약 예시에는 시연용 값을 사용한다.
페이지 크기는 기본 10개·최대 100개이며 목록은 items와 페이지 정보를 제공한다.
페이지 메타데이터의 실제 필드명은 상세 명세에서 합의한다.
화면 하단 번호는 1~10, 11~20처럼 묶어 표시한다.

## 2. BE 코드에서 문서 정보 정의하기

초기 구현 후 저장소 구조에 맞춰 다음 정보를 API 코드에 작성한다.

1. Router에 경로·메서드·성공 상태 코드와 기능 태그를 정의한다.
2. 요청·쿼리 모델에 타입, 기본값, 허용 범위와 필드 설명을 작성한다.
3. 응답 모델 또는 반환 타입으로 성공 응답 구조를 정의한다.
4. 주요 오류 응답 모델과 상태 코드를 OpenAPI에도 선언한다.
5. 요약·설명·시연용 예시를 추가한다.
6. 공통 오류 처리에서 실제 응답이 code·message·request_id 계약을 따르도록 구현한다.

FastAPI 기본 검증 오류 응답은 프로젝트 공통 형식에 맞춰 예외 처리와 문서 선언을 함께 조정한다.
문서에 오류 형식을 선언하는 것과 실제 예외 처리 구현을 함께 검증한다.

공식 참고 자료는 [응답 모델](https://fastapi.tiangolo.com/tutorial/response-model/), [오류 처리](https://fastapi.tiangolo.com/tutorial/handling-errors/), [태그·문서 URL 설정](https://fastapi.tiangolo.com/tutorial/metadata/)이다.

## 3. FE·BE가 /docs에서 실제 요청 확인하기

이 절차는 로컬·테스트 환경의 시연 계정을 사용한다. Execute는 실제 API를 호출하며 변경 API는 해당 환경의 데이터를 바꾼다.

1. BE/README.md의 실제 명령으로 서버와 DB를 준비한다.
2. 안내된 서버 주소에 /docs를 붙여 접속한다. 서버가 http://localhost:8000인 경우 http://localhost:8000/docs가 된다.
3. 확인할 API를 펼쳐 경로·요청 필드·성공 및 오류 스키마를 API_SPEC.md와 비교한다.
4. ‘Try it out’을 누르고 시연용 입력값을 채운다.
5. ‘Execute’를 눌러 실제 상태 코드와 JSON 응답을 확인한다.
6. 빈 결과·입력 오류·다른 역할의 접근·수정 충돌 등 해당 API의 실패 상황도 확인한다.
7. 오류의 request_id와 서버 로그가 연결되는지 BE 담당자가 확인한다.

개별 경로는 실제 구현·계약을 따른다. 이 가이드의 서버 주소는 예시이며 현재 실행 중임을 의미하지 않는다.

### 쿠키 인증 API 확인

1. 같은 서버의 /docs에서 실제 로그인 API를 호출한다.
2. 브라우저 개발자 도구에서 로그인 응답의 Set-Cookie와 쿠키 설정 여부를 확인한다.
3. 다음 인증 요청에 필요한 쿠키가 전송되는지 확인한다.
4. 상태 변경 요청에는 구현한 CSRF 규칙에 맞는 헤더·값도 전달한다. 실제 이름과 발급 절차는 API_SPEC.md에 기록한다.
5. 로그아웃 후 쿠키 제거·리프레시 폐기 동작을 확인한다.

HttpOnly 쿠키는 브라우저가 관리한다. Swagger의 Bearer 입력만으로 쿠키 로그인을 대체하지 않는다.
Swagger에서 설정한 CSRF 헤더가 실행 요청에 포함되는지 개발자 도구로 확인한다.
쿠키·CSRF 동작은 자동 문서 화면에서 확인한 뒤 실제 FE 출처에서도 테스트한다. SameSite·Secure·Domain·Path·CORS 설정이 환경별 요청에 영향을 줄 수 있다.

## 4. 계약과 구현의 일치 확인하기

BE는 구현한 API 테스트에서 정상·오류 응답의 상태 코드와 필수 구조를 검증한다.
주요 항목은 역할·소유권·상태별 권한, soft delete, 버전 충돌, 중복 요청과 통계 계산이다.
응답 모델에는 민감 필드가 노출되지 않는지도 확인한다.
공통 오류 처리 변경은 검증 오류·인증 실패·업무 오류가 같은 계약을 유지하는지 검사한다.

자동 문서의 스키마와 실제 테스트 응답을 비교하고, FE는 화면에서 사용하는 필드·타입·시간·빈 결과를 확인한다.
OpenAPI 출력이 생성되는 사실만으로 계약 검증이 완료되지는 않는다.
실제 pytest·Ruff·mypy 실행 명령과 테스트 DB 초기화 명령은 초기 구성 후 BE/README.md와 TEST_PLAN.md에 기록한다.

## 5. API 변경을 MR에 반영하기

1. API_SPEC.md에서 변경 목적과 요청·응답 차이를 갱신한다.
2. FE 호출부에 영향을 주는 필드·타입·필수값 변경은 FE 담당자와 적용 순서를 맞춘다.
3. 요청·응답 모델, Router 문서 선언, 공통 오류 처리와 관련 테스트를 갱신한다.
4. 로컬·테스트 환경에서 /docs와 실제 응답을 확인하고 저장소의 검증 명령을 실행한다.
5. dev에서 분기한 작업 브랜치의 MR을 dev로 보낸다. 실행한 검증과 남은 항목을 MR에 적는다.

리뷰에서는 계약 문서·OpenAPI·실제 응답·FE 호출부의 필드가 일치하는지 확인한다.
운영의 문서 화면 공개 범위와 접근 제어는 배포 환경을 정할 때 결정한다.
