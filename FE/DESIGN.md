# DESIGN.md

목적: 사출반장의 일관된 UXUI 구현 및 디자인 협업 기준

### 적용 규칙

1. 모든 UI는 정의된 공통 규격을 사용한다.
2. 기존 컴포넌트를 우선 재사용한다.
3. 임의의 크기·간격·모서리 값을 추가하지 않는다.
4. 예외가 필요하면 디자인 담당자와 협의 후 문서를 갱신한다.

## 1. 디자인 방향

사출반장은 사출성형 업무를 효율적으로 관리하기 위한 웹앱이다.

- **명확성:** 생산 정보와 설비 상태를 직관적으로 전달한다.
- **효율성:** 업무에 필요한 정보에 빠르게 접근할 수 있어야 한다.
- **일관성:** 동일한 기능과 상태에는 동일한 디자인을 적용한다.
- **신뢰성:** 중요한 데이터와 경고를 정확하게 표현한다.
- **간결성:** 불필요한 장식보다 정보의 가독성을 우선한다.

## 3. 레이아웃

**우선 사용 환경: 사무실 PC**

- 데스크톱 사용성을 최우선으로 설계한다.
- 좌측 사이드바와 메인 콘텐츠 영역을 기본 구조로 사용한다.
- 선택된 메뉴는 Primary 컬러로 표시한다.
- 데이터 테이블, 차트, 수치를 읽기 쉽게 배치한다.
- 동일한 페이지 구조와 여백 규칙을 유지한다.
- 모바일·태블릿 확장 가능성을 고려하되, 세부 기준은 추후 확정한다.

### 글자 크기 토큰

CSS에서는 px 값을 직접 쓰지 않고 `global.css`의 `--fs-*` 토큰만 사용한다. 새 크기가 필요하면 디자인 담당자와 협의 후 단계를 추가한다.

| 토큰 | 크기 | 주 용도 |
| --- | --- | --- |
| `--fs-xs` | 12px | 캡션, 배지, 차트 축 (최소 크기) |
| `--fs-sm` | 14px | 보조 텍스트 |
| `--fs-md` | 16px | 테이블 |
| `--fs-lg` | 18px | 본문, 버튼·입력창 |
| `--fs-xl` | 20px | 카드 제목, 사이드바 |
| `--fs-2xl` | 24px | 섹션 제목 |
| `--fs-3xl` | 28px | 강조 수치 |
| `--fs-4xl` | 32px | 페이지 제목 |
| `--fs-5xl` | 36px | KPI |

- 12px 미만은 사용하지 않는다.
- 예외: 로고 문구(`YOUR FACTORY PARTNER`)와 로그인 화면 대형 문구는 로고·브랜드 요소로 보고 토큰을 적용하지 않는다.

공통 버튼, 입력창, 카드, 테이블은 재사용 가능한 컴포넌트로 관리한다.

## 5. UI 디자인 규격

### 모서리 (Border Radius)

- 버튼·입력창: `10px`
- 카드·모달: `16px`
- 알림 배지: `9999px`
- 작은 UI 요소: `6px`
- CSS에서는 토큰만 쓴다: `--radius-small`(6) · `--radius-control`(10) · `--radius-card`(16) · `--radius-pill`(9999). 원형은 `50%`, 2px 이하 범례 표식만 예외.
- 글자 굵기는 400 / 500 / 600 / 700만 쓴다.

### 간격 (Spacing)

- 기본 간격 단위: `4px`
- 사용 간격: `4 / 8 / 12 / 16 / 20 / 24 / 32 / 48px`
- 카드 내부 여백: `24px`
- 페이지 콘텐츠 여백: `32px`
- 컴포넌트 간 기본 간격: `16px`

### 크기 (Sizing)

- 사이드바 너비: `240px`
- 사이드바 메뉴 높이: `48px`
- 버튼 높이: `44px`
- 작은 버튼 높이: `36px` (글자 14px·아이콘 16px, 카드·구역 제목 옆 보조 동작. 클래스 `button-sm`)
- 입력창 높이: `44px`
- 테이블 행 높이: `48px`

### 테두리 및 그림자

- 기본 테두리: `1px solid #E2E2E8`
- 카드 배경: `#FFFFFF`
- 기본 카드 그림자: 없음
- 팝오버 그림자: `0 4px 16px rgba(41, 38, 63, 0.12)`

### 컴포넌트 상태

- **Default:** 기본 상태
- **Hover:** 마우스 오버 시 시각적 피드백
- **Focus:** 키보드 탐색 시 명확한 테두리 표시
- **Disabled:** 비활성화 상태
- **Loading:** 처리 중 상태 표시 및 중복 실행 방지
- **Error:** 오류 내용과 복구 방법 안내

### 세그먼트 컨트롤

- 공통 컴포넌트 `components/SegmentedControl` 하나만 사용한다. 페이지별로 선택 스타일을 새로 만들지 않는다.
- 역할은 **모드 전환**(오늘/이번주, 일간/주간/월간)과 **필터**(전체/대기/진행 중/완료)로 나뉘지만 선택 표현은 같다.
- 트랙: `--soft` 배경 · `1px` 테두리 · `--radius-control` · 안쪽 여백 `4px`
- 선택: `--surface` 배경 · `1.5px` `--primary` 테두리 · `--primary` 글자. 보라 채움은 주요 버튼에만 쓴다.
- 크기: `sm`(버튼 높이 `28px`, 카드 제목 옆) / `md`(버튼 높이 `34px`, 툴바·필터 줄). 다른 높이를 만들지 않는다.
- 개수 배지(선택 시 연보라)와 색 점(점검·납품·회의)은 컴포넌트 슬롯으로만 쓴다. 경고 의미가 있는 개수만 앰버색을 허용한다.
- 좁은 화면에서는 컨트롤이 가로로 스크롤되고, 바깥 줄이 먼저 줄바꿈된다.
- 같은 항목 수의 컨트롤이 같은 폭으로 보이도록 세그먼트 최소 폭을 `sm` 72px, `md` 90px로 둔다. 긴 라벨은 최소 폭을 넘을 때만 늘어난다.

### 조회 조건 카드

- 생산·검사 이력과 품질 리포트는 `components/QueryFilterCard`를 함께 사용한다.
- 제목은 `CalendarDays` 아이콘 + "조회 조건", 오른쪽에 빠른 기간 `SegmentedControl`과 `초기화` 버튼을 둔다.
- 제목은 `--fs-lg`(18px)·600, 필드 라벨과 값은 `--fs-sm`(14px)로 위계를 둔다.
- 필드는 `조회 기간(시작—종료)` + 제품 + 설비의 3열(`2fr 1fr 1fr`)로 배치한다. 1100px 이하 2열, 720px 이하 1열.
- 기간 입력은 두 날짜 필드를 `—`로 묶고, 오류는 공통 경고 박스로 표시한다.
- 카드 하단에는 시연 기준일과 조회 가능한 데이터 범위를 캡션으로 적는다.

## 6. 핵심 화면

현재 확인된 메뉴:

1. 과거 대화 이력 + 검색
2. 실시간 공정
3. 올라온 보고
4. 재고 관리
5. 일정 상세
6. 품질 리포트
7. 생산·검사 이력

각 화면은 공통 레이아웃과 디자인 규칙을 따른다.

화면별 상세 기능, 정보 구조, 권한 및 예외 상황은 별도의 기능 명세를 따른다.

첨부된 대시보드 이미지는 레이아웃 및 시각적 위계의 참고 자료이며, 색상·글자·간격·컴포넌트 규격은 DESIGN.md를 우선한다.

## 7. UX 및 인터랙션

- 주요 기능은 최소한의 클릭으로 접근할 수 있도록 한다.
- 중요한 수치와 상태는 명확하게 표시한다.
- Loading / Empty / Error / Success 상태를 설계한다.
- 저장, 수정, 삭제 결과를 사용자에게 안내한다.
- 데이터 손실 위험이 있는 작업에는 확인 또는 복구 수단을 제공한다.
- 테이블의 숫자, 단위, 정렬과 상태 표현을 통일한다.
- 키보드 조작과 명확한 Focus 표시를 지원한다.
- 일반 텍스트는 WCAG AA 대비 기준을 목표로 한다.
- 수치는 천 단위 구분 기호를 사용한다. 예: `5,232개`
- 숫자는 기본적으로 오른쪽 정렬한다.
- 비율의 소수 자릿수와 날짜·시간 형식을 지표별로 통일한다.
- 실시간 데이터는 마지막 갱신 시각을 표시한다.
- 데이터 없음(`—`)과 값이 0인 상태(`0`)를 구분한다.

## 8. 협업 및 AI 작업 규칙

1. 기존 디자인과 공통 컴포넌트를 먼저 확인한다.
2. 정해진 컬러, 폰트, 간격 규칙을 준수한다.
3. 기존 화면과 다른 디자인을 임의로 도입하지 않는다.
4. 신규 컴포넌트가 필요하면 재사용 가능성을 검토한다.
5. 정상·로딩·빈 화면·오류 상태를 함께 고려한다.
6. 디자인 변경이 필요하면 이유와 영향 범위를 공유한다.
7. 확정된 변경사항은 디자인 문서와 실제 구현에 함께 반영한다.
